# 자산 시뮬레이터 모바일 기간 선택 정리와 사용법 모달 캐러셀화

모바일에서 최대 기간(연도) 선택 UI를 칩 리스트에서 셀렉트로 바꾸고, 긴 기간을 고를 때 슬라이더 마커가 너무 촘촘해지는 문제를 정리했다. 이어서 첫 방문 시 뜨는 "사용법" 온보딩 모달을 텍스트 목록에서 실제 화면 스크린샷을 곁들인 드래그 가능한 캐러셀로 전면 개편했다.

## 모바일 기간 선택: 칩 → 셀렉트, 마커 밀도 조정

`HORIZON_PRESET_YEARS`(5/10/20/30년) 칩 리스트는 데스크톱에서만 보이도록(`@min-[500px]:flex`) 남기고, 모바일에서는 `TimelineSlider`의 "지금" 라벨과 같은 행 반대쪽 끝에 `CustomSelect`를 배치했다. `TimelineSlider`에 `rightSlot` prop을 추가하고 `AssetAreaChart`를 거쳐 `AssetSimulator`가 모바일 전용 셀렉트 노드를 내려보내는 구조다.

20년/30년처럼 긴 기간에서는 슬라이더 원형 마커가 1년/5년 단위라 지나치게 촘촘했다. `horizonMonths > 120`일 때 마커 간격을 12개월/60개월(1년/5년, minor/major)에서 60개월/120개월(5년/10년)로 전환하도록 `TimelineSlider`를 수정했다.

이 작업 중 두 가지 z-index 버그를 발견했다:

- **드롭다운이 형제 카드에 가려짐**: `AssetAreaChart` 카드가 `backdrop-blur`로 새 스태킹 컨텍스트를 만들어, 내부 드롭다운의 `z-20`이 DOM상 뒤에 오는 형제 카드(자산 비교)에 가려졌다. 카드 자체에 `relative z-20`을 줘서 해결.
- **드롭다운이 슬라이더 마커에 가려짐**: 마커/썸/레인지 인풋이 드롭다운과 같은 스태킹 컨텍스트에서 DOM 순서상 뒤에 있어 항상 위에 그려졌다. 슬라이더 트랙 컨테이너에 `relative z-0`을 줘서 자체 스태킹 컨텍스트로 격리해 해결.

입력 패널을 접었을 때 접기 버튼과 그래프 패널 사이 여백이 고정 `mb-4`라 과도하게 크던 문제도 함께 정리했다 — 접힘 + 모바일일 때만 `mb-0`으로 줄였다.

## 사용법 모달: 텍스트 목록 → 이미지 캐러셀

기존 온보딩 모달은 5개 항목(입력 패널/자산 추이·자금 흐름/비교·비율·구성/누적 이력/시나리오)을 한 줄짜리 굵은 라벨 + 짧은 설명으로만 나열했다. 여러 라운드에 걸쳐 다음과 같이 발전시켰다.

**이미지 추가.** Playwright로 실제 시뮬레이터 화면(예시 시나리오 상태)을 데스크톱/모바일 각각 캡처해 `public/playground/asset-simulator/onboarding/`에 저장하고, 슬라이드마다 이미지+라벨+설명을 갖춘 카드로 구성했다. `next/image`의 `fill` + `object-contain`으로 슬라이드마다 다른 실제 화면 비율(가로로 넓은 입력 패널, 세로로 긴 누적 이력 등)을 잘림 없이 표시하고, `min-[500px]:` 뷰포트 미디어 쿼리로 뷰어의 실제 화면 폭에 맞는 이미지 세트를 고른다. 누적 이력 패널은 `@max-[1400px]:hidden`이라 모바일에 아예 렌더링되지 않으므로, 이 슬라이드만 모바일에서도 데스크톱 스크린샷을 그대로 재사용한다.

**문구 보강.** "자산·수입·지출·이체를 등록하세요" 같은 4~5단어짜리 요약을, 실제로 무엇을 할 수 있는지 설명하는 문장으로 바꿨다. "막막하다면 예시 시나리오부터 살펴보세요" 안내는 처음엔 캐러셀 아래 별도 인디고 박스로 뒀다가, 시나리오 슬라이드 설명 문장에 자연스럽게 포함시키는 방식으로 정리했다.

**드래그 가능한 캐러셀.** 버튼/닷 전용 슬라이드 전환을, 모바일 그래프 패널 캐러셀과 동일한 `overflow-x-auto` + `snap-x snap-mandatory` 네이티브 스크롤 방식으로 바꿨다. 터치는 네이티브 스크롤-스냅이 그대로 처리하지만, 데스크톱 마우스 클릭-드래그는 `overflow-x-auto`가 기본으로 반응하지 않으므로 `mousedown`/`mousemove`/`mouseup`을 직접 연결해 커서를 따라가는 드래그 스크롤을 구현했다.

드래그 도중 스크롤이 안 되는 버그가 있었다: `scroll-snap-type: x mandatory`가 걸린 채로 JS가 `scrollLeft`를 수동으로 바꾸면, 브라우저의 네이티브 스냅 로직이 중간에 개입해 가장 가까운 슬라이드로 순간 이동시켜버려 커서를 매끄럽게 따라가지 못했다. 드래그 시작 시 `scroll-snap-type: none`으로 끄고 드래그 종료 후 복원하는 방식으로 해결했다.

**순서 배지 고정.** 처음엔 "n/5" 배지를 슬라이드마다 하나씩 이미지 안에 넣었는데, 사용자가 카드마다 있는 게 아니라 고정 위치에 있어야 한다고 지적 — 스크롤 영역 바깥에 배지 하나만 두고 현재 슬라이드 인덱스로 텍스트만 갱신하도록 바꿨다.

**버튼 클릭 시 문구 깜빡임.** 화살표 버튼으로 슬라이드를 넘기면 `scrollTo(behavior:"smooth")` 호출과 동시에 상태를 즉시 갱신했는데, 애니메이션 도중 계속 발생하는 `scroll` 이벤트가 중간 스크롤 위치를 반올림해 상태를 여러 번 다시 바꿔버려 문구가 깜빡였다. 스크롤 이벤트를 120ms 디바운스해 "완전히 멈춘 뒤 한 번만" 상태를 갱신하도록 수정해 해결했다.

## 새로 배운 것

- `backdrop-filter`(`backdrop-blur` 등)는 `position`+`z-index` 조합 없이도 새 스태킹 컨텍스트를 만든다 — 카드형 UI에 흔한 유리효과 클래스가 내부 팝오버의 `z-index`를 의도치 않게 가둘 수 있다.
- CSS `scroll-snap-type`은 JS로 `scrollLeft`를 직접 조작하는 커스텀 드래그와 충돌한다 — 네이티브 스냅과 수동 드래그를 함께 쓰려면 드래그 중엔 스냅을 꺼야 한다.
- 스크롤에 연동된 React 상태는 `scroll` 이벤트를 그대로 반영하면 애니메이션 중간값 때문에 깜빡일 수 있어, "스크롤이 멈춘 뒤"를 감지하는 디바운스가 필요하다.
