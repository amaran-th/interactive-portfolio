# 자산 시뮬레이터 차트 레이아웃 안정화와 파이 차트 라벨 재설계

차트 패널 5개(자산 추이·자금 흐름·자산 비교·자산 비율·수입/지출 구성)의 크기 불균형을 해소하고, 도넛 차트의 범례를 없애고 바깥쪽 라벨로 교체했다. 이 과정에서 반응형 그리드가 서로 다른 두 컨테이너 폭을 참조할 때 생기는 비단조적 레이아웃 전환 버그를 세 차례에 걸쳐 진단하고 고쳤다.

## 패널 재배치: 2행, 비율 조정

"자금 흐름은 작고 자산 비교는 크다", "자산비율과 수입지출 구성 크기 차이가 크다"는 제보를 계기로 5개 패널을 재배치했다. 행 개수는 2개로 고정하고(사용자 요청), 각 행 안에서 패널이 차지하는 비율을 콘텐츠 특성에 맞게 조정하는 방향으로 풀었다:

- 1행: 자산 추이 + 자금 흐름 — 둘 다 "가로로 넓은" 콘텐츠라 각 50%
- 2행: 자산 비교(25%) + 자산 비율(25%) + 수입/지출 구성(50%)

수입/지출 구성은 내부에 도넛 2개(수입/지출)가 있고, 이 둘이 나란히 놓이려면 자기 폭이 420px를 넘어야 하는 내부 브레이크포인트(`@min-[420px]:flex-row`)가 있다. 50% 비율을 줘야 이 기준을 만족해 세로로 쌓이지 않는다.

자산 비율(`GroupDonutChart`)은 패널 폭이 33%→25%로 줄면서, 도넛+바깥쪽 라벨을 담는 박스가 고정 픽셀 크기(344px)라 폭만 flexbox에 눌려 줄어들고 높이는 그대로 남는 버그가 생겼다 — 원이 정사각형이 아닌 세로로 긴 박스 안에 위치해 아래로 치우쳐 보였다. 도넛 크기·여백 상수(`SIZE`, `LABEL_MARGIN`)를 좁아진 폭에 맞게 축소해 해결했다.

## 파이 차트: 범례 → 바깥쪽 라벨 + 리더 라인

`GroupDonutChart`, `FlowRatioChart`의 `<ul>` 범례 목록을 없애고, 각 조각의 중간 각도를 계산해 링 바깥에 라벨을 직접 배치하는 방식으로 바꿨다. 진행 과정:

1. 15% 이상 큰 조각만 링 안쪽에 흰 글씨로 직접 라벨링 (범례는 유지)
2. "범례 없애고 바깥에 라벨" 요청 → 범례 완전 제거, 모든 조각에 바깥쪽 라벨 (점 마커 + 텍스트)
3. "점 대신 선으로" → 조각 색과 같은 색의 짧은 리더 라인으로 교체
4. "선-텍스트 간격이 좁다" → 라인이 끝나는 지점(`LABEL_GAP`)과 텍스트가 시작하는 지점(`TEXT_GAP`)을 분리해 여백 확보, 0%로 반올림되는 조각은 라벨 생략
5. "라벨이 카드 밖으로 삐져나감"(50:50처럼 큰 조각이 수평 방향을 가리킬 때) → 라벨을 고정 너비 + `break-keep`로 감싸 카드 안에서 두 줄로 줄바꿈되게 함

바깥쪽 라벨 리팩터링 도중 호버 툴팁이 깜빡이는 버그도 발견했다 — 새로 추가한 툴팁 wrapper div에 `pointer-events-none`이 빠져서, 툴팁이 뜨는 순간 마우스 이벤트를 가로채 hover-leave가 반복 발생하는 루프였다.

## 스택 순서와 증감액 표시

`AssetAreaChart`(자산 추이)와 `ComparisonBarChart`(자산 비교) 둘 다, 스택 그리기 순서가 배열 순서와 같다는 점을 이용해 기본 자산이 항상 맨 아래(가장 먼저 그려지는 밴드)에 오도록 정렬 로직을 수정했다. 기존엔 미분류 자산이 그룹 뒤에 정렬돼 기본 자산이 스택 맨 위로 가는 경우가 많았다.

- `ComparisonBarChart`: "지금" 대비 선택 시점의 총자산 증감액을 `(+1,905만원)` 형태로, 결과 금액 위에 괄호로 감싸 표시.
- `FlowDiagram`(이번 달 자금 흐름으로 개명): 기본 자산 칩 안에 전월 대비 증감액을 이름과 최종 금액 사이 세 번째 줄로 표시. 칩 안 다른 텍스트와 형식을 맞춰 `formatKRW`(만원 단위) 대신 원 단위 그대로 표기.

## 반응형 브레이크포인트: 세 차례의 비단조 버그

누적 이력(`HistoryPanel`)의 유무를 결정하는 바깥 그리드와, 차트 패널 열 개수를 결정하는 안쪽 그리드가 처음엔 **같은 `@container`를 공유**했다. 이력 패널이 나타나며 차트 컬럼 폭을 갑자기 줄여도, 안쪽 그리드는 그 사실을 모른 채 "전체 컨테이너가 900px 넘었으니 4열"로 판단해버려, 실제로는 훨씬 좁아진 폭에 4열이 욱여넣어지는 문제가 있었다.

세 라운드에 걸쳐 정리했다:
1. 차트 컬럼(`chartsColumnRef`) 자체에 중첩 `@container`를 선언 — 안쪽 그리드가 이력 패널이 차지한 만큼 줄어든 실제 폭을 기준으로 판단하게 함
2. "이력 패널이 먼저 사라지고 그 다음 레이아웃이 바뀌어야 한다"는 우선순위 요청 — 이력 패널 표시 기준을 900px→1250px로 상향
3. "레이아웃이 바뀌었다가 이력 패널이 사라지며 원복했다가 다시 바뀐다"는 비단조 현상 발견 — 이력 패널이 있을 때도 차트 컬럼 폭이 이미 4열 기준(1000px)을 넘도록 이력 패널 기준을 1400px까지 재상향, 전 구간에서 열 개수가 단조 증가하도록 확정

핵심 교훈: 형제 그리드가 폭을 나눠 가지는 구조에서는, 한쪽의 브레이크포인트 숫자가 다른 쪽이 나타나는 시점에도 이미 안전한 쪽에 있도록 여유를 둬야 비단조적 플립플롭을 막을 수 있다.

## 기타

- 모바일 캐러셀(이전/닷/다음) 컨트롤을 연도 프리셋 버튼 바로 아래에서 모든 차트 패널 뒤(맨 아래)로 이동.
- standalone 페이지(`(services)/asset-simulator`)의 이중 `max-w` 래퍼가 뷰포트보다 좁을 때 여백에 검은 배경이 드러나던 문제를 배경을 `main`으로 옮겨 해결. sticky 헤더를 콘텐츠 최대 너비 제한 바깥으로 빼서 헤더 배경은 전체 폭, 내부 콘텐츠는 제한된 폭을 갖게 재구성. 헤더 아래 컨테이너에 상단 패딩 추가.
- 수입/지출/이체 목록에 `max-h-80 overflow-y-auto` 적용, `useDragReorder` 훅에 스크롤 컨테이너 ref를 받아 드래그 중 포인터가 리스트 상/하단 48px 안쪽에 들어가면 자동 스크롤되도록 확장 — 슬롯 판정과 드래그 아이템의 transform 모두 스크롤량만큼 보정해 커서와 어긋나지 않게 함.
