# 네모네모빔 모바일 편집기 재구성 — 이비스페인트식 레이아웃과 핀치 줌

모바일 편집기의 화면 배치를 이비스페인트를 참고해 다시 짜고, 두 손가락 핀치
줌을 추가했다. 디자인 시스템(색상 토큰·버튼 스타일·`FLOATING_PANEL`)은 그대로
두고 레이아웃과 상호작용만 바꿨다.

바로 앞 설계였던 세로 도구 열(`2026-10-04-nemo-nemo-beam-mobile-tool-rail.md`)은
이 설계로 대체됐다 — 그 문서가 설명하는 `MobileToolRail.tsx`는 삭제됐으므로,
모바일 도구 UI의 현재 모습은 이 문서를 기준으로 본다.

## 화면 배치

```
┌─────────────────────────────────────┐
│ ‹ 파일명 ...  [저장됨] [레이어모드] [저장] │  ← 상단 바
├─────────────────────────────────────┤
│[↶][↷]   [1.5x]      [▭][⌁][✥][⟡]   │  ← 캔버스 오버레이: 좌상단 되돌리기/다시실행,
│                                       │     중앙 배율 배지(핀치 중에만), 우상단 모드 도구
│              canvas                  │
│                                       │
│      [지금 도구의 하위 옵션]           │  ← 상시 노출 옵션 strip(반투명, 중앙정렬)
├─────────────────────────────────────┤
│  [펜/지우개][그리기도구][색상][레이어][더보기] │  ← 하단 독(아이콘만, 라벨 없음)
└─────────────────────────────────────┘
```

## 도구 그룹 분리

이비스페인트처럼 도구를 두 종류로 나눴다.

- **모드 도구**(선택·올가미·이동·자동 선택): 캔버스 우상단에 상시 노출, 탭 한
  번으로 즉시 전환. 활성 도구를 다시 탭하면 해제되고 직전 그리기 도구로 돌아간다.
- **그리기 도구**(연필·지우개·채우기·직선·사각형·원·텍스트·그라데이션): 하단 독의
  "그리기 도구" 버튼을 눌러 열리는 그리드 피커에서 고른다. 버튼 아이콘은 지금
  활성인 그리기 도구를 그대로 보여준다.
- 별도로 **펜↔지우개 토글**이 독 맨 앞에 있다. 지우개면 펜으로, 그 외 어떤
  도구든 누르면 펜이 된다 — 피커를 열지 않고 오가는 지름길이라 아이콘은 상태와
  무관하게 고정(순환 화살표 + 붓 + 지우개 합성, `PenEraserIcon.tsx`)이다.

## 하위 옵션 계산 공유

"어떤 도구가 어떤 하위 옵션을 갖는지"는 `DrawToolbar.tsx`의
`buildSecondarySections`라는 순수 함수 하나로 모았다. 데스크탑은 이 결과를
섹션마다 흰 패널로 나눠 캔버스 하단에 포털로 띄우고, 모바일은 같은 결과를
반투명 패널 하나에 가로로(넘치면 줄바꿈) 모아 캔버스 위에 오버레이로 띄운다.
계산은 완전히 공유하고 감싸는 모양만 다르다.

옵션 strip은 오버레이지만 바깥 래퍼가 `pointer-events-none`이라, 패널이 실제로
덮는 자리만 탭을 가로채고 그 바깥 캔버스는 그대로 그릴 수 있다.

## 핀치 줌

두 손가락으로 확대/축소한다. 감지는 도구별 포인터 핸들러와 완전히 분리된
`window` 레벨 리스너로 두는데, 한쪽 손가락이 캔버스 바깥 여백에 닿는 경우까지
잡아야 하기 때문이다(도구 핸들러는 `<canvas>`에만 붙어 있다).

- **배율**은 `ZOOM_STEPS` 단계에 맞추지 않고 연속값으로 바뀌며 `[0.1, 8]`로
  클램프된다. 제스처가 끝나도 스냅하지 않는다 — `nextZoomStep`이 배열에 없는
  값을 받아도 다음/이전 단계를 올바르게 찾으므로 데스크탑 +/- 버튼과 섞여도 된다.
- **핀치 중심점**이 화면에서 고정되도록 스크롤을 매 프레임 보정한다. 중심점
  아래의 캔버스 좌표는 제스처 **시작 시점에 한 번만** 구해 고정하고, 이후
  프레임은 그 값과 현재 손가락 중심점만으로 계산한다 — 매 프레임 현재 상태를
  되읽으면 React state의 비동기 커밋 지연이나 브라우저의 스크롤 클램프가 다음
  프레임으로 번져 오차가 누적된다.
- 배율이 바뀔 때마다 캔버스를 중앙으로 재정렬하던 기존 effect는 핀치 중에만
  건너뛴다(그대로 두면 핀치의 스크롤 보정을 매번 덮어쓴다).
- 모바일에는 좌하단 +/- 컨트롤을 띄우지 않는다. 배율은 핀치 중에만 상단 중앙
  배지로 잠깐 보여준다. 데스크탑은 핀치가 없으므로 +/- 버튼과 배율 숫자를 그대로 둔다.

### 두 번째 손가락이 그려버리는 문제

두 번째 손가락의 `pointerdown`은 캔버스의 bubble 단계 핸들러(React 루트 위임)에
먼저 도착해 그리기를 시작해버리고, 뒤늦게 실행되는 핀치 감지가 부르는
`handlePointerCancel`이 그것까지 커밋했다 — 핀치할 때마다 점이 하나씩 찍혔다.

해결: 핀치의 `pointerdown` 리스너를 **capture 단계**로 등록하고, 추적 중인
포인터가 2개가 되는 바로 그 이벤트에만 `stopPropagation()`을 부른다. capture
단계는 이벤트가 대상까지 내려가기 전에 실행되므로 캔버스 핸들러가 아예 실행되지
않는다. 첫 손가락(카운트 1)은 그대로 통과시켜 평소 그리기에 영향이 없다.

진행 중이던 스트로크 자체는 새 취소 로직 없이 기존 `handlePointerCancel`
(=`handlePointerUp`, 인자 없는 멱등 함수)을 그대로 호출해 "지금까지 그린 그대로
손을 뗀 것처럼" 마무리한다 — 시스템 제스처가 스트로크를 끊는 경우를 위해 이미
만들어져 있던 경로다.

### 터치 제스처 충돌

`<canvas>`에는 `touch-none`이 있지만 그 바깥 여백(같은 스크롤 뷰포트 안)은
기본값이라, 양손가락이 전부 여백에 닿으면 브라우저 자체의 페이지 핀치줌이 JS
핀치와 동시에 발동할 수 있었다. 뷰포트에 `touch-action: pan-x pan-y`를 줘서
한 손가락 스크롤은 유지하면서 네이티브 두 손가락 핀치만 막는다.

## Tailwind v4 클래스 우선순위 함정

모드 도구 줄의 활성 버튼이 흰 배경 + 흰 아이콘으로 렌더돼 아예 안 보이는 버그가
있었다. `FLOATING_PANEL`(`bg-white ring-1 ...`)과 활성 상태의 `bg-violet-500`을
한 `className`에 함께 넣은 것이 원인이다.

**`className` 문자열 안의 순서는 우선순위와 무관하다** — 생성된 스타일시트에서
나중에 선언된 규칙이 이기고, Tailwind v4는 테마 변수 순서대로 유틸리티를
출력하는데 `--color-white`가 `--color-violet-500`보다 뒤에 있어 `bg-white`가
항상 이겼다.

해결: 그 버튼만 `FLOATING_PANEL`을 쓰지 않고 `ring`/`shadow`를 직접 쓰고, 배경색은
활성/비활성 삼항으로 **상호 배타적으로** 만들어 두 `bg-*`가 애초에 공존할 수
없게 했다. 공용 스타일 상수에 `bg-*`가 들어 있을 때 조건부 배경색을 덧붙이면
언제든 재발할 수 있는 종류의 버그다.
