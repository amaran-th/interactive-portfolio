# 네모네모빔 이미지 불러오기 — 대표색 추출 median cut 교체와 패널 UX 정리

## 대표색 추출 알고리즘 교체

기존 파이프라인은 두 단계였다.

1. `reducePaletteFast` — 원본 팔레트가 256색을 넘으면 RGB 채널을 성글게
   반올림해 버킷으로 묶어 후보 수를 빠르게 줄인다. 대표는 버킷에서 처음 만난
   색(임의).
2. `quantizeColors` — 팔레트가 목표 개수를 넘는 동안, 모든 색 쌍의 RGB
   유클리드 거리를 계산해 가장 가까운 쌍을 병합한다. 반복당 O(색상수²),
   총 O(색상수³).

한계:

- **픽셀 빈도를 전혀 보지 않는다.** 1픽셀짜리 희귀색과 화면 절반을 차지하는
  색이 병합 우선순위에서 동등하게 취급된다.
- 거리 척도가 단순 RGB 유클리드라 지각적으로 맞지 않는다.
- O(색상수³)이라 팔레트가 크면 느리다.

이를 **빈도 기반 median cut**(`quantizeMedianCut`) 하나로 대체했다.

1. `pixels` 배열을 스캔해 팔레트 색별 등장 횟수를 집계하고, 한 번도 쓰이지
   않은 색은 버린다.
2. 전체 색을 담은 박스 하나에서 시작해, 목표 개수만큼 박스가 생길 때까지:
   - **분할할 박스** = 채널별 (max − min)에 luma 계수(0.299 / 0.587 / 0.114)를
     곱한 "가중 범위"가 가장 큰 박스. 동점이면 픽셀 수가 많은 쪽.
   - 그 박스의 색을 가장 긴 가중 축으로 정렬하고, **누적 픽셀 수가 절반이
     되는 지점**(population median)에서 둘로 나눈다.
3. 각 박스의 대표색 = 빈도 가중 무게중심(centroid)을 구한 뒤, **그 박스 안에
   실제로 있던 색 중 무게중심에 가장 가까운 것**. 평균색을 새로 만들지 않아
   "대표색은 항상 이미지에 있던 색"이라는 성질을 유지한다.
4. 원래 팔레트 인덱스 → 새 대표 인덱스로 `pixels`를 다시 매핑한다.

반복당 O(색상수), 총 O(maxColors · 색상수) 수준이라 사전 감축 단계 없이 한
번에 처리한다. `reducePaletteFast`, `quantizeColors`, 미사용이 된
`colorDistance`를 제거했다.

## 대표 색상 개수 슬라이더의 동적 상한

`quantizeColors`는 `maxColors ≥ 현재 팔레트 수`이면 더 줄일 게 없어
그대로 반환한다. 즉 슬라이더에서 그 위 값은 무의미하다.

`runPixelate`가 픽셀화 직후 `raw.palette.length`(그 해상도·안티에일리어싱에서
실제로 뽑히는 고유색 수)를 `availableColors`로 저장하고, 슬라이더·숫자 입력의
`max`를 `min(256, availableColors)`로 잡는다. 라벨에는 고유색이 256 이하면
`이 사진 최대 N`, 넘으면 도구 상한임을 뜻하는 `최대 256`을 보여준다.

## 원본 비율 유지

기존에는 `pixelateImage(img, size, size, aa)`로 항상 정사각형 격자에 그려
넣어, 비율이 다른 사진이 1:1로 찌그러졌다. `runPixelate`가 `img.naturalWidth
/ naturalHeight`로 **긴 변이 `size`가 되도록** 격자 크기를 계산하고 짧은 변은
비례로 맞춘다(예: 400×150 → 32×12). 픽셀 해상도 라벨 옆에 실제 결과 크기
`W×H`를 표시한다.

## 패널 배치 정리

- **추출된 색상 팔레트**를 슬라이더·캔버스 크기 설정 아래에서 **미리보기
  캔버스 바로 아래**로 옮겼다. 팔레트는 추출 결과물이므로 미리보기와 붙어
  있어야 한다. 헤더에 "추출된 색상" 개념 자체가 생소하다는 피드백을 받아
  도움말 툴팁을 붙였다.
- **병합 확정 버튼**을 스와치 격자 위에서 아래로 옮겼다. 격자 위에 있을 때는
  2번째 색을 선택하는 순간 버튼이 나타나 스와치가 아래로 밀려, 3번째를
  누르려던 손이 빗나갔다. 격자 아래로 옮기고, 병합 모드인 동안은 (선택이 2개
  미만이어도) 항상 같은 높이를 차지하게 해 레이아웃이 고정되도록 했다.
- **해상도·캔버스 크기 섹션**을 서로 붙였다("얼마나 큰가"를 정하는 짝).
  안티에일리어싱·대표 색상 개수는 그 아래로.
- **캔버스 크기 규격 프리셋 목록**(`CANVAS_PRESET_GROUPS`)을 감췄다 — 새 캔버스
  흐름에서 대부분 픽셀 해상도 그대로거나 폭×높이 직접 입력이라 잘 안 쓰였다.
- **"픽셀 해상도와 동일"을 토글**로 바꿔, 켜져 있으면 폭×높이 입력을 비활성화
  (캔버스 크기 = 픽셀 해상도라 편집할 게 없음). 다시 누르면 현재 크기를
  시작값으로 직접 편집.
- **네이티브 `<input type=file>` 크롬 숨김** — "파일 선택 / 선택된 파일 없음"
  기본 문구 대신, 드래그 안내 문구 안의 "파일을 선택"을 텍스트 버튼으로.
