# 글자수 세기: 제한 초과분 하이라이트와 자동 저장

글을 쓰거나 붙여 넣으면 바로 글자 수를 세는 도구다(`/char-counter`, 카테고리 생산성). 자기소개서처럼 분량 제한이 있는 글을 다듬을 때 쓴다.

## 세는 방식 (`count.ts`)

- **공백 포함·제외**: `Intl.Segmenter`(grapheme)로 센다. 합쳐진 이모지(👨‍👩‍👧)는 한 글자다. 공백 제외는 띄어쓰기·탭·줄바꿈을 모두 뺀다.
- **바이트**: 두 가지다. 한글 2(ASCII 1, 나머지 2, EUC-KR 셈법)와 UTF-8.
- **단어·줄·문단**: 단어는 공백으로 나뉜 덩어리, 문단은 빈 줄로 나뉜 덩어리다. `\r\n`은 `\n`으로 바꿔서 센다.
- **`overflowStart(text, limit, basis)`**: 기준대로 세다가 제한을 처음 넘기는 글자의 UTF-16 인덱스를 돌려준다. 공백 제외 기준에서는 공백이 제한을 넘기지 못하므로, 넘기는 다음 글자부터다. 테스트로 `countText`의 합과 경계가 맞는지 기준마다 확인한다.
- 처음에는 웹 양식에 맞춰 줄바꿈을 2자로 세는 옵션이 있었다. 화면을 단순하게 하려고 뺐고, 이 차이는 FAQ로 안내한다.

## 화면 (`CharCounter.tsx`)

- **넘친 부분 하이라이트**:
  - textarea는 글 일부에만 색을 넣을 수 없다. 그래서 같은 글을 뒤 층(`aria-hidden`)에 투명 글자로 겹쳐 그리고, 넘친 부분만 `<mark>` 배경으로 칠한다.
  - 두 층은 같은 상자 규칙(`FIELD`: padding·글꼴·`whitespace-pre-wrap`·`scrollbar-gutter: stable`)을 써서 줄바꿈 위치가 같다. 스크롤은 `onScroll`로 맞춘다.
- **제한**:
  - 기준(공백 포함·공백 제외·바이트)과 숫자를 고른다. 숫자 칸은 직접 입력하거나 목록(300~1,500)에서 고른다.
  - 고른 기준의 숫자 옆에 `/제한`를 붙이고 남색으로 강조한다. 넘으면 빨갛게 바뀐다.
  - 진행 막대는 입력칸 아랫변에 겹쳐 그려, 제한을 정하고 지워도 배치가 바뀌지 않는다.
- **글자 수 줄**:
  - 평소에는 공백 포함·제외 두 칸만 보이고, 나머지는 '자세히'로 펼친다.
  - 바이트를 제한 기준으로 고르면 둘째 칸이 바이트로 바뀐다. 윗줄이 늘 두 칸이라 좁은 화면에서도 줄이 넘치지 않는다.
- **선택 부분**: 드래그하면 입력칸 오른쪽 아래에 고른 부분의 글자 수 배지를 띄운다.
- **맞춤법 검사**:
  - 스위치로 textarea의 `spellcheck`를 켠다.
  - 외부 검사기 연동도 검토했다. 하지만 글을 서버로 보내지 않는다는 원칙과 맞지 않아 브라우저 기능만 쓴다.

처음에는 '목표'라고 불렀으나, 분량 상한이라는 뜻이 분명하도록 화면 문구를 '제한'으로 바꿨다. 코드의 `limit` 이름은 그대로다.

## 드롭다운 (`_shared/Dropdown.tsx`)

- **두 가지 칸**:
  - `Select`: 버튼을 누르면 목록이 열린다.
  - `NumberCombo`: 숫자를 직접 적는 입력칸에 프리셋 목록과 × 버튼을 붙였다. ×는 값이 없어도 자리를 지켜 칸 폭이 흔들리지 않는다.
- **동작**: 화면 아래쪽에 있어서 목록은 위로 연다. 방향키로 고르고 Enter로 정하며, Esc나 바깥을 누르면 닫는다.
- **포커스**: 목록 항목에서 `pointerdown` 기본 동작을 막아 포커스를 입력칸에 둔 채 고른다.
- 공통 훅이 ref가 든 객체를 돌려주면 React Compiler lint가 렌더 중 ref 접근으로 판단한다. 그래서 구조 분해해서 쓴다.

## 저장

- **저장 키**: `localStorage` `char-counter`에 `{ text, limit, basis, spellcheck }`를 저장한다. 예전에 저장된 `crlf` 값은 버리고, `spellcheck`가 없으면 끈 것으로 읽는다.
- **저장 시점**: 입력이 멈추고 2초 뒤에 저장한다. `visibilitychange`(hidden)·`pagehide`·`beforeunload`에서는 기다리지 않고 바로 저장한다.
- **상태 표시**: 제목 옆에 '자동 저장됨'을 보인다. 저장에 실패하면 '저장하지 못했어요'로 바뀌고, 이때만 `beforeunload` 확인을 띄운다.
