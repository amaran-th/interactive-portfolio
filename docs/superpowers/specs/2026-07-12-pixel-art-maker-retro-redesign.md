# 픽셀아트 메이커 라이트모드 + 레트로 데스크탑 재디자인 — 설계 문서

## 개요

`픽셀아트 메이커`(Work #5)는 기능 구현이 모두 끝난 뒤(Task 1-14 + 최종 whole-branch 리뷰) 실제 화면을 확인한 결과, 다크 테마·일반 Tailwind 카드 UI가 "너무 세련되어" 원래 의도한 "도트 기반 윈도우 OS 데스크탑" 느낌과 맞지 않는다는 피드백을 받았다. 브라우저 기반 시각 동반자로 여러 라운드의 목업을 비교하며 다음 방향으로 수렴했다.

이 문서는 **비주얼 재디자인 범위**만 다룬다. 데스크탑/캔버스의 기능 로직(드래그, 다중선택, 선택 도구, 저장/내보내기 등)은 이미 구현·리뷰가 끝났고 변경하지 않는다 — 오직 색상·테두리·폰트·컴포넌트 구조(팔레트→색상환)만 바뀐다.

## 배경: 왜 재디자인하는가

- 프로젝트 전역 컨벤션(`CLAUDE.md`)은 다크 테마이지만, 이 Work는 명시적 예외로 라이트모드를 쓴다 — 사용자가 최종 결과물을 보고 직접 요청.
- 목업 반복 과정(굵은 픽셀 테두리 → 얇은 테두리 → 테두리 없음 → 라운딩 없음 → 폰트로 레트로감 보강)을 통해, "레트로"의 정체성을 **테두리·베벨 같은 UI 크롬이 아니라 도트 아이콘 그림 + 도트 폰트**로 표현하는 쪽으로 합의했다. 나머지 카드·메뉴 크롬은 오히려 모던(그림자 기반, 무테두리, 각진 모서리)하게 유지한다.

## 1. 비주얼 시스템

| 항목 | 값 |
|---|---|
| 배경 | 크리스프 화이트 `#ffffff` |
| 포인트 컬러 | 바이올렛 계열 `#8b5cf6` (호버/활성 상태, 컨텍스트 메뉴 강조 항목 등) |
| 테두리 | 없음 — 모든 분리는 `box-shadow`로만 표현 |
| 모서리 | 각짐(`border-radius: 0`), 라운딩 없음 |
| 폰트 | `public/fonts/Mona12.ttf` / `Mona12-Bold.ttf` (한글 도트 폰트, 이미 리포에 추가됨) — `next/font/local`로 로드 |
| 적용 범위 | 픽셀아트 메이커 전체(데스크탑 화면 + 편집기 화면) |

목업에서 검증된 3가지 톤(쿨 그레이+블루 / 웜 크림+코랄 / 크리스프 화이트+바이올렛) 중 **크리스프 화이트+바이올렛**을 확정했다.

### Tailwind 클래스 치환 방향
기존 다크 클래스(`bg-gray-950`, `text-white`, `border-white/10`, `bg-white/5` 등)를 다음으로 치환한다:
- `bg-gray-950` → `bg-white`
- `text-white` → `text-gray-900` (또는 상황에 따라 `text-gray-700`)
- `border-white/10`, `border-white/20` 등 **테두리 클래스는 전부 제거**하고 `shadow-sm`/`shadow-md`/`shadow-lg`로 교체
- `bg-white/5`, `bg-white/10`(패널 배경) → `bg-gray-50` 또는 흰 배경 + 그림자
- 활성/호버 강조 색은 바이올렛 계열(`bg-violet-500`, `text-violet-600`, `hover:bg-violet-50` 등)로 통일
- 모든 `rounded-*` 클래스 제거(각진 모서리 유지)

## 2. 도트 폰트 통합

- `Mona12.ttf`(레귤러), `Mona12-Bold.ttf`(볼드) 두 파일을 `next/font/local`로 로드하는 폰트 정의를 추가한다.
- 적용 대상: 픽셀아트 메이커의 모든 UI 텍스트(데스크탑 아이콘 라벨, 컨텍스트 메뉴, 툴바 툴팁, 편집기 헤더, 다이얼로그, 팔레트/색상환 라벨 등). 픽셀아트 캔버스 자체의 그림 내용에는 영향 없음(폰트는 UI 텍스트 전용).
- 다른 Work나 사이트 전역 폰트(Geist Sans/Mono)에는 영향을 주지 않는다 — 이 Work 트리 안에서만 지역적으로 적용.

## 3. 휴지통 아이콘

기존 `lucide-react`의 `Trash2` 아이콘을 걷어내고, 도트로 직접 그린 휴지통 그래픽으로 교체한다.
- 평상시(닫힌 뚜껑) / 드래그오버 시(열린 뚜껑 또는 강조 테두리 느낌의 다른 프레임) 최소 2가지 상태를 시각적으로 구분한다.
- 구현 방식: 고정 픽셀 그리드를 하드코딩한 작은 `<canvas>` 렌더러로 그린다 — `DesktopIcon.tsx`가 이미 쓰는 픽셀 그리드 렌더링 패턴(2차원 배열 순회 + `fillRect`)을 그대로 재사용해 코드 스타일을 통일한다. 별도 이미지 파일 에셋은 만들지 않는다(에셋 없는 프로젝트 철학 유지).

## 4. 팔레트 → 색상환 위젯 (PalettePanel 전면 교체)

기존 `PalettePanel.tsx`(hex `<input type="color">` + "색상 추가" 버튼 + 스와치 그리드)를 다음 동작으로 교체한다.

- **항상 떠 있는 원형 HSV 컨트롤**: 휴(hue)·채도(saturation)를 원형 휠로, 명도(value/brightness)는 별도 슬라이더로 조작. 툴바 영역에 상시 노출(모달이 아님).
- **직접 편집 방식**: 색상환을 조작하면 **현재 활성 팔레트 색상(activeColorIndex가 가리키는 스와치)의 값이 실시간으로 바뀐다.** 즉 "새 색을 고르고 추가"가 아니라 "지금 선택된 색을 수정"이 기본 동작이다.
- **팔레트 스와치 목록**: 여전히 그리드로 존재하며, 스와치를 클릭하면 그 스와치가 활성 색상이 되고 색상환이 그 색의 H/S/V로 즉시 동기화된다.
- **새 색 추가**: 스와치 목록 끝에 있는 "+" 스와치를 누르면, 그 시점의 색상환 값이 새 스와치로 팔레트에 추가되고 활성 색상이 그 새 스와치로 바뀐다.
- 팔레트 색상 개수 제한(16색)은 기존과 동일하게 유지 — "+"는 16개에 도달하면 비활성화.
- 스와치 더블클릭으로 제거하는 기존 동작은 유지.

### 색상환 ↔ 캔버스 도구 연동
- 스포이트로 캔버스에서 색을 뽑으면(`onPickColor`) 활성 색상 인덱스가 바뀌고, 색상환도 그 색의 H/S/V로 동기화되어야 한다.
- 색상환 조작은 팔레트 배열 자체(`doc.palette[activeColorIndex]`)를 직접 갱신하므로, `Editor.tsx`의 `hasMetaEdits` 미저장 상태 플래그도 함께 갱신해야 한다(기존 `handleAddColor`/`handleRemoveColor`가 이미 이렇게 처리하는 패턴을 그대로 따름).
