# 자산 시뮬레이터: 음수 잔액 렌더링 수정, 자금 흐름도 재설계, 전체 레이아웃 재구성

v1~v3(4라운드까지) 구현·리뷰가 완료된 상태에서, 사용자가 실제 사용 중 발견한 버그 리포트와 레이아웃 개선 요청을 반영하는 새 라운드다.

## 배경

사용자가 "기본 계좌가 비어있을 때 지출이 발생하면 그래프가 이상해 보인다"고 제보했다. 조사 결과:

- `simulation.ts`의 기본 계좌 수입/지출 처리(`balances[primary.id] += incomeIn` / `-= expenseOut`)에는 클램핑이 전혀 없다. 이체 규칙(`Math.max(0, Math.min(requested, sourceBalance))`)과 달리, 지출은 잔액과 무관하게 그대로 차감되어 잔액이 무제한으로 음수가 될 수 있고 그 상태로 복리 성장까지 계속된다.
- `AssetAreaChart.tsx`의 스택 폴리곤 계산(`bottom`/`top` 누적합 → `[...topPoints, ...bottomPoints.reverse()]`)은 모든 자산 값이 0 이상이라고 가정하고 작성되어, 값이 음수가 되는 순간 자기교차하는("나비넥타이") 도형을 만든다. 숫자 합계는 맞지만 시각적으로 진짜 깨진다. `ComparisonBarChart.tsx`도 동일한 reduce 기반 세그먼트 스태킹 구조라 같은 문제를 갖는다.
- 별개로 `FlowDiagram.tsx`는 `destinationTotals` 집계 시 `transfer.fromAssetId`로 필터링하지 않아, 기본계좌가 아닌 다른 자산 간 이체 규칙까지 전부 기본계좌에서 나가는 것처럼 잘못 그려지는 버그가 있다.

여기에 더해 사용자는 자금 흐름도의 시각적 가독성 개선과, 입력 패널 위치·현재 자산 표시 방식·타임라인 슬라이더 위치를 포함한 전체 페이지 레이아웃 재구성을 요청했다.

## 1. 음수 잔액 렌더링 수정

**`simulation.ts`는 변경하지 않는다** — 잔액이 부족한데 지출이 발생하면 실제 재정 상황처럼 잔액이 음수가 되는 것이 맞는 동작이다(사용자 확정).

**`AssetAreaChart.tsx`**: 현재 `scaleY`는 `maxTotal = Math.max(1, ...snapshots.map(s => s.totalBalance))`만 계산해 0을 y축 하단 고정 기준으로 삼는다. 이를 다음과 같이 바꾼다:

- 각 자산 밴드의 스택 계산(`prevTop`/`top` reduce)에서 나오는 모든 `top`/`bottom` 값 중 최솟값(`minValue`, 0 이하일 수 있음)과 최댓값(`maxValue`)을 함께 추적한다. **최댓값도 반드시 누적 스택 기준으로 추적해야 한다** — 자산 순서에 따라 스택 중간의 누적 top이 최종 총합(`maxTotal`)보다 커질 수 있으므로(예: 큰 양수 자산이 먼저 쌓이고 그 뒤에 음수 자산이 쌓이는 경우), `maxTotal`만으로는 부족하다. (초기 구현에서 이 부분이 누락되어 특정 자산 순서에서 밴드가 차트 밖으로 잘리는 버그가 있었음 — 최종 라운드 리뷰에서 발견·수정됨.)
- y축 스케일 도메인을 `[Math.min(0, minValue), Math.max(1, maxTotal, maxValue)]`로 확장한다. 0선은 도메인 안의 한 지점이 되며, 값이 모두 0 이상이면 기존과 동일하게 차트 하단이 곧 0선이다.
- 밴드가 0선 아래로 내려가는 부분은 자연스럽게 0선 아래 영역에 그려진다(더 이상 top/bottom이 역전되지 않음 — 스택 순서는 여전히 각 자산의 실제 누적 위치를 따르되, 개별 자산 값이 음수면 그 자산의 top이 bottom보다 아래(화면상 위)로 가지 않고 정상적으로 bottom보다 작은 값(더 마이너스)이 되어 폴리곤이 뒤틀리지 않는다).
- 0선 아래로 내려간 폴리곤 구간은 별도 색(rose/red 계열, 예: `fill="#f43f5e"` 계열)으로 틴트해 적자 구간을 시각적으로 구별한다. 이 틴트는 SVG `clipPath`로 0선 아래 영역만 잘라서 오버레이하는 방식으로 구현하며(자산 자체 값의 부호가 아니라 실제 렌더링된 픽셀 위치 기준), 오버레이에는 반드시 `pointerEvents="none"`을 줘서 밑에 깔린 원래 폴리곤의 툴팁(`<title>`)을 가리지 않게 한다. 0선 자체는 얇은 기준선(예: 회색 점선)으로 그린다.
- 현재(t=0) 시점 총자산을 그래프 내부에 고정 마커/라벨로 표시한다 — 기존의 움직이는 커서 라인(선택된 월 추적)과는 별개로, x=0 위치에 고정된 점/라벨을 추가해 "지금" 값을 항상 볼 수 있게 한다. 기존 상단 "총자산 {금액}" 타이틀은 그대로 유지(선택된 월 기준 값 표시 역할).
- 타임라인 슬라이더가 이 컴포넌트 안으로 통합되므로(4번 항목 참고), 자산이 하나도 없어 차트를 그릴 데이터가 없는 상태에서도 슬라이더는 항상 렌더링되어야 한다 — 빈 상태 플레이스홀더로 컴포넌트 전체를 조기 반환(early return)하면 슬라이더까지 함께 사라지므로, 바깥 카드는 항상 유지하고 차트 대 플레이스홀더만 조건부로 바꾼다.

**`ComparisonBarChart.tsx`**: 동일한 원리로 `buildSegments`의 세그먼트 스태킹에 0 기준선을 도입한다(위 `AssetAreaChart.tsx`와 마찬가지로 최솟값과 최댓값을 모두 누적 스택 기준으로 추적). 자산 세그먼트가 음수면 막대가 0선 아래로 확장되고, 그 구간은 rose 계열로 틴트한다 — 이 틴트도 `AssetAreaChart.tsx`와 동일하게 `clipPath` 오버레이(`pointerEvents="none"` 포함) 방식으로 구현해, "이 자산의 값이 음수인가"가 아니라 "이 세그먼트의 픽셀이 실제로 0선 아래에 있는가"를 정확히 반영한다. 양수 자산/이체 막대는 기존과 동일하게 0 위로 유지된다.

## 2. FlowDiagram 버그 수정 + 재설계

**버그 수정**: `destinationTotals` 집계 시 `transfer.fromAssetId === primaryAsset.id`인 이체만 포함하도록 필터링한다. 기본계좌가 아닌 자산 간 이체는 이 다이어그램에 나타나지 않는다(기존에도 기본계좌 중심 다이어그램이었고, 이 라운드는 "모든 자산 간 흐름을 다 보여주는" 일반 네트워크 그래프로의 확장을 원하지 않는다고 확인됨 — 기본계좌 중심 구조 유지, 정확성만 수정).

**기본계좌 노드 음수 표시**: `primaryAsset`의 잔액(`snapshot.assetBalances[primaryAsset.id]`)이 음수면 해당 노드를 빨간색 계열(`color`)로 표시하고 금액 앞에 `-` 부호가 명확히 보이도록 한다(현재도 `Math.round(amount).toLocaleString()`이 음수를 처리하지만 노드 색상은 고정 `#4338ca`이므로 구별이 안 됨).

**레이아웃 재설계**: 데이터 구조(수입→기본계좌→[지출+이체 목적지])는 그대로 유지하되, 시각적 가독성을 개선한 형태로 다시 그린다. 정확한 노드 배치·크기·연결선 스타일은 구현 단계(계획 작성 시)에서 확정한다 — 사용자가 제시한 스케치(수입→기본계좌→지출, 기본계좌에서 여러 자산군으로 분기)를 참고하되 다른 레이아웃도 허용됨.

## 3. 전체 페이지 레이아웃 재구성

페이지 세로 순서(위 → 아래), 변경 사항만 표시:

1. 제목/가로프리셋/환율 — 변경 없음
2. `ScenarioTabs` — 변경 없음
3. `ScenarioComparisonChart` — 위치 변경 없음(현재 위치 그대로, 전체 폭)
4. **[신규]** 입력 패널 5개 카드 — `GroupAssetSection`(현재 자산), `IncomeSection`, `ExpenseSection`, `TransferRuleSection`, `GoalCard`를 전체 폭 반응형 그리드로 배치. 이 라운드에서 `GoalCard`가 처음으로 "입력 패널" 그룹에 합류한다(기존에는 별도 상단 요약 행에 있었음). 5장이라 2열로 딱 나뉘지 않으므로, 정확한 열 개수(3열 등)와 마지막 줄 처리 방식은 구현 단계에서 결정한다 — 5장이 한 줄에 억지로 쌓이거나 어색하게 잘리지 않도록 자연스럽게 줄바꿈되면 된다.
5. **[신규]** 2열 구조: 왼쪽(넓은 쪽)은 차트 영역, 오른쪽(사이드바)은 `HistoryPanel`(누적 이력) — 기존 3열 구조(입력패널/차트/이력)에서 입력패널이 위로 빠지면서 2열이 됨.
   - 차트 영역 내부, 위→아래: `AssetAreaChart`(헤어 차트, 전체 폭, `TimelineSlider`를 카드 내부/하단에 통합, t=0 현재자산 마커 포함) → 그 아래 `ComparisonBarChart`/`GroupDonutChart`/`FlowDiagram`/`CashFlowChart` 2×2 그리드.

기존 상단 "현재 자산" 요약 스탯 카드(`💰 현재 자산` + 금액)는 제거된다 — 그 역할은 이제 `AssetAreaChart`의 타이틀(선택 시점 값)과 t=0 고정 마커(현재 값)가 대신한다.

`TimelineSlider`의 기능(선택된 월 → 전체 차트/패널이 공유하는 `selectedMonth` state 갱신)은 변경하지 않는다 — 시각적 위치만 `AssetAreaChart` 카드 내부/하단으로 옮긴다.

## 엣지 케이스

- 음수 잔액 상태에서도 자산 추가/삭제/색상 변경 등 기존 조작은 전부 동일하게 동작해야 한다 — 렌더링 수정은 순수 시각화 레이어이며 시뮬레이션 데이터나 사용자 조작 로직을 바꾸지 않는다.
- 여러 자산이 동시에 음수인 경우(드문 경우: annualReturnRate가 음수인 자산 등)에도 스택 계산이 깨지지 않아야 한다 — 도메인 확장은 전체 스냅샷의 최솟값을 기준으로 하므로 자연스럽게 처리된다.
- `GoalCard`가 입력 패널 그룹으로 이동해도 목표 설정/진행률 계산 로직은 변경되지 않는다 — 위치만 이동.
- `AssetAreaChart`의 t=0 마커는 시나리오 전환 시(다른 시나리오 탭 선택) 그 시나리오의 t=0 값으로 즉시 갱신되어야 한다(기존 `key={activeScenarioId}` 리마운트 패턴에 이미 포함되는 컴포넌트가 아니므로, props로 전달되는 `snapshots[0]` 값이 바뀌면 자연히 갱신됨 — 별도 상태 동기화 불필요).

## 범위 밖 (Non-goals)

- `FlowDiagram`을 기본계좌 중심이 아닌 모든 자산 간 흐름을 보여주는 일반 네트워크 그래프로 확장하지 않는다.
- `GroupDonutChart`(그룹별 비율)의 음수 처리는 이번 범위에 포함하지 않는다 — 파이/도넛 차트는 비율(ratio) 기반이라 음수 값의 의미가 다르고(원형 차트에서 "음수 비율"은 시각적으로 정의하기 애매함), 사용자도 이를 요청하지 않았다.
- 슬라이더의 기능적 동작(공유 `selectedMonth`, horizon-preset과의 상호작용 등)은 바꾸지 않는다 — 시각적 위치 이동만.
- 새 색상 팔레트나 디자인 시스템 변경은 하지 않는다 — 기존 색상 토큰(rose/red 계열은 이미 지출 카드 등에서 사용 중)을 그대로 활용한다.
