# 네모네모빔 모바일 편집기 레이아웃 재구성 (ibisPaint 참고) 설계 문서

## 배경

2026-10-01~04에 걸쳐 모바일 도구 선택 UI를 하단 독 팝오버 → 캔버스 왼쪽
세로 아이콘 열로 재설계했다(`2026-10-01-nemo-nemo-beam-mobile-tool-rail-design.md`).
완성 직후 "실제 드로잉 앱(ibisPaint)과 레이아웃 자체가 다르다"는 피드백이
나왔고, 스크린샷을 참고해 화면 전체 요소 배치를 다시 짰다. 이번 설계는
**디자인 시스템(색상 토큰·버튼 스타일·`FLOATING_PANEL` 등)은 그대로 두고
레이아웃/배치/UX만** ibisPaint에 맞춰 재구성한다.

## 범위

- 모바일(`narrow`) 편집기 화면 전체의 요소 배치. 데스크탑 `DrawToolbar`
  렌더링(`mobileLayout` 미지정 경로)은 건드리지 않는다.
- 도구별 하위 옵션을 "어떤 도구가 어떤 옵션을 갖는지" 계산하는 로직
  (`secondarySections`, `DrawToolbar.tsx`)은 그대로 재사용 — 감싸는
  위치·상시 노출 여부만 바꾼다.
- 색상/레이어 패널 내부, "더보기"의 파일·편집 항목 내용은 변경 없음 —
  꺼내는 버튼 위치만 바뀐다.
- 캔버스 줌 컨트롤(`canvasArea` 안, `bottom-2 left-2`)은 공유 코드라
  변경하지 않는다.

## 전체 배치

```
┌─────────────────────────────────────┐
│ ‹ 파일명 ...  [저장됨] [레이어모드] [저장] │  ← 기존 상단 바(변경 없음, 되돌리기·다시실행만 제거)
├─────────────────────────────────────┤
│[↶][↷]      [▭][⌁][✥][⟡]            │  ← 캔버스 위 오버레이: 좌상단 되돌리기/다시실행,
│                                       │     중앙 모드 도구 줄(선택·올가미·이동·자동선택)
│                                       │
│              canvas                  │
│                                       │
│                      [축소 100% 확대] │  ← 기존 줌 컨트롤(변경 없음)
├─────────────────────────────────────┤
│  [지금 도구의 하위 옵션 — 항상 보임]    │  ← 신규: 상시 노출 옵션 strip
├─────────────────────────────────────┤
│  [그리기 도구] [색상] [레이어] [더보기] │  ← 하단 메인 줄(기존 독 대체)
└─────────────────────────────────────┘
```

## 도구 그룹 분리

ibisPaint는 도구를 "모드 도구"(선택·이동·가이드 — 각자 바로 탭)와
"그리기 도구"(브러시 종류가 많아 피커로 묶음) 두 그룹으로 나눈다. 네모
네모빔의 12개 도구를 이 구조에 맞춘다:

- **상단 모드 도구 줄** (캔버스 위 오버레이, 각자 바로 탭하면 즉시 전환):
  선택 · 올가미 · 이동 · 자동 선택 (`SELECT_TOOLS`, 기존 상수 재사용)
- **하단 그리기 도구 피커** (하단 메인 줄의 "그리기 도구" 버튼 → 그리드
  패널): 연필 · 지우개 · 채우기 · 직선 · 사각형 · 원 · 텍스트 · 그라데이션
  (`PRIMARY_DRAW_TOOLS` + `COLLAPSIBLE_DRAW_TOOLS`, 기존 상수 재사용)

두 그룹 중 어느 쪽에서 고르든 `onToolChange`는 동일하게 호출된다 —
도구 자체의 동작·하위 옵션 계산은 지금과 완전히 같다.

## 상시 노출 옵션 strip

기존 `secondarySections`/`mobileOptionsNode`(2026-10-01 설계에서 만든,
섹션 여러 개를 패널 하나에 세로로 모으는 로직)를 그대로 재사용하되,
**"도구를 다시 탭해야 열림"이 아니라 하단 메인 줄 바로 위에 항상 떠 있는
in-flow 영역**으로 바꾼다. 이비스페인트의 "브러시 크기/불투명도 슬라이더
상시 노출"과 같은 자리·같은 원칙이다.

- 내용은 지금 활성 도구의 `secondarySections`를 그대로 반영 — 도구를
  바꾸면(모드 줄이든 그리기 피커든) 이 영역 내용도 즉시 바뀐다.
- "불투명도" 슬라이더는 넣지 않는다 — 대응하는 기능(브러시 자체의
  불투명도 조절)이 데스크탑에도 없어서, 이번 레이아웃 재구성 범위 밖의
  새 기능이 된다. 필요해지면 별도 스펙으로.
- 옵션이 없는 도구(텍스트)는 이 영역이 빈 상태(최소 높이로 접힘)가
  된다 — 도구마다 옵션 유무가 달라 영역 높이가 바뀌는 건 자연스러운
  결과로 받아들인다(기존 2026-10-01 설계도 같은 전제).
- 캔버스 밀어내기(실제 레이아웃 폭/높이 차지) vs 오버레이 — 이 strip은
  **실제 레이아웃 높이를 차지**한다(오버레이 아님). 이비스페인트의
  슬라이더가 캔버스를 오버레이로 가리지 않고 항상 그 아래 고정 공간을
  차지하는 것과 같다. 상시 노출이라 "그 순간 가려서 못 그린다"는
  문제가 세로 열 때처럼 생기지 않는다 — 항상 같은 자리에 있어 사용자가
  그 영역을 피해서 그리면 되기 때문이다.

## 상단 오버레이 (되돌리기/다시실행 + 모드 도구 줄)

- **되돌리기/다시실행**: 상단 바(헤더)에서 제거하고, 캔버스 위 좌상단에
  떠 있는 작은 버튼 두 개로 옮긴다. 헤더는 엄지가 닿기 먼 자리라는
  피드백 — 캔버스 오버레이는 손이 더 가깝다.
- **모드 도구 줄**(선택·올가미·이동·자동선택): 캔버스 위 상단 중앙에
  떠 있는 가로 아이콘 줄. 되돌리기/다시실행과 겹치지 않게 중앙~중앙
  우측에 둔다.
- 둘 다 캔버스 영역의 `relative` 래퍼 안에 `absolute`로 배치 — 기존
  줌 컨트롤(`bottom-2 left-2`)과 같은 레이어 관례.
- 이 둘은 **모바일 전용** 신규 UI다 — 데스크탑은 되돌리기/다시실행이
  이미 "편집" 카드에, 선택 도구들은 "선택·조작" 카드에 있으므로 그대로
  둔다.

## 하단 메인 줄 (기존 독 대체)

4개 버튼: **그리기 도구 · 색상 · 레이어 · 더보기**.

- 기존 "도구" 탭(2026-10-01에 제거)이 "그리기 도구" 버튼으로 되살아나되,
  이번엔 선택 계열 4개가 빠진 8개 그리기 도구만 다룬다.
- "그리기 도구" 버튼 아이콘은 지금 활성 도구가 이 8개 중 하나면 그
  도구 아이콘으로 보여준다. 모드 도구 줄 쪽(선택·올가미·이동·자동선택)이
  활성이면 고정값으로 펜슬 아이콘을 보여준다 — "마지막으로 쓴 그리기
  도구를 기억" 같은 추가 상태는 두지 않는다(단순함 우선, 어차피 버튼을
  누르면 그리드가 열려 바로 고를 수 있다).
- 탭하면 기존 색상/레이어/더보기와 같은 방식(독 위에 뜨는
  `FLOATING_PANEL` 팝오버)으로 8개 도구 그리드가 열린다. 고르면
  팝오버가 닫히고 도구가 바뀐다 — 옵션은 상시 노출 strip에 바로
  반영되므로 별도의 "자동 열림/안 열림" 분기가 필요 없다(2026-10-01
  설계에서 복잡했던 지점이 이번엔 구조적으로 사라진다).
- **보조색(secondary color) 버튼은 따로 만들지 않는다** — 기존
  "색상" 패널(`ColorWheel`)이 이미 `activeColorHex`/`secondaryColorHex`
  둘 다 다루므로, 별도 진입점을 추가하면 중복이다.
- 색상/레이어/더보기 버튼과 그 팝오버 내용·동작은 변경 없음.

## 참조 레이어 경고 배너

`Editor.tsx`의 "참조 레이어로 지정된 레이어가 없습니다" 배너
(`bottom-14` 고정)는 하단에 상시 노출 strip이 새로 생기는 만큼 겹치지
않도록 오프셋을 조정한다 — 기능 변경 없음, 위치 상수만 수정.

## 모바일 키보드와 하단 바

텍스트 도구로 글자를 입력하면 화면 아래에서 가상 키보드가 올라온다 —
하단 메인 줄과 상시 옵션 strip을 전부 화면 맨 아래에 두는 이번
설계에서 키보드가 그 위를 덮어버리지 않는지 확인이 필요한 지점이다.

- 지금 구조(헤더-캔버스-하단바가 `position: fixed` 오버레이가 아니라
  실제 flex 레이아웃)에서는, 대부분의 모바일 브라우저가 키보드가 뜰 때
  **레이아웃 뷰포트 자체를 줄여서** 캔버스 영역(`flex-1`)만 작아지고
  하단 바는 그 줄어든 화면 맨 아래에 그대로 남는다 — 하단 바를
  `position: fixed`로 만들었다면 실제로 키보드에 가려졌을 것이다.
- 일부 브라우저/웹뷰는 레이아웃 뷰포트를 안 줄이고 키보드를 기존
  화면 위에 그냥 덮어버리기도 한다 — 이 경우 하단 바가 가려질 수 있다.
- 텍스트 도구 자체의 하위 옵션(`secondarySections`)은 없으므로 옵션
  strip은 이미 빈 상태로 접혀 있다. 텍스트 입력 중 실제로 조작이
  필요한 커밋/취소 등은 `PixelCanvas`가 캔버스 위에 직접 띄우는
  `pendingText` 전용 컨트롤(이번 설계 범위 밖, 기존 그대로)이 맡는다 —
  하단 바까지 손이 갈 필요가 꼭 있는 건 아니다.
- 구현 후 실제 기기(iOS Safari·Android Chrome 등)에서 텍스트 도구로
  키보드를 띄워 하단 바가 가려지는지 반드시 확인한다. 가려진다면
  `visualViewport` API로 키보드 높이를 감지해 하단 바를 그 위로
  올리는 보강이 필요하다 — 이번 스펙 범위 밖, 실기기 확인 후 필요하면
  후속 작업으로.

## 컴포넌트 구성 (구현 시 고려사항)

`MobileToolRail.tsx`(2026-10-01에 만든 세로 열 + 오버레이 플라이아웃)는
이번 설계로 대체된다 — 세로 열이라는 단일 시각 요소가 아니라 서로 다른
화면 위치에 흩어지는 3개 조각(상단 모드 줄, 하단 도구 피커, 상시 옵션
strip)이 되므로, `DrawToolbar.tsx`의 `mobileLayout` 분기가 하나의
컴포넌트에 위임하는 대신 이 3개를 **별도 조각으로 분리해 반환**해야
한다. `MobileEditorShell.tsx`가 지금 `toolPanel` 하나로 받는 자리를
`modeToolsRow`/`drawToolPicker`/`optionsStrip` 3개 prop으로 나누는 안을
우선 검토한다(정확한 타입·배선은 플랜 단계에서 확정).

되돌리기/다시실행 오버레이는 `MobileEditorShell.tsx` 자신이 캔버스
래퍼 안에 직접 그린다(모바일 전용 신규 UI라 `DrawToolbar`를 거칠
필요가 없다 — `canUndo`/`canRedo`/`onUndo`/`onRedo`는 이미
`MobileEditorShellProps`에 있다).

## 테스트 / 검증 계획

자동 테스트 없음 — `tsc`/`lint`(baseline 0 errors, 9 warnings) +
브라우저 수동 검증.

- 상단 좌: 되돌리기/다시실행 동작 확인(disabled 상태 포함).
- 상단 중앙: 선택/올가미/이동/자동선택 각각 탭 → 즉시 전환, 하단
  옵션 strip에 해당 도구 옵션(선택 모드/전역 동일색/대상 레이어 등)이
  바로 반영되는지.
- 하단 "그리기 도구" → 그리드에서 연필~그라데이션 8개 선택 → 전환 +
  strip에 브러시 크기/채우기/그라데이션 옵션 반영.
- 텍스트 도구 선택 시 strip이 빈 상태로 접히는지.
- 색상/레이어/더보기 버튼 기존 동작 회귀 없는지.
- 참조 레이어 경고 배너가 strip과 안 겹치는지.
- (실기기 확인) 텍스트 도구로 키보드를 띄웠을 때 하단 바가 가려지는지.
- 데스크탑(`narrow=false`) 회귀 없는지(그리기/선택·조작/편집 카드,
  캔버스 하단 포털 그대로).

## 범위 밖

- 불투명도 슬라이더(대응 기능 없음).
- 캔버스 축소 미리보기(내비게이터) — ibisPaint 스크린샷에 있었지만
  이번 요청·논의에서 다루지 않았다.
- "그리기 도구" 버튼의 구체적 아이콘 전환 애니메이션 등 디테일.
