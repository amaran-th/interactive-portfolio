# 네모네모빔 모바일 셸 — 도구바(DrawToolbar) 모바일 내부 구성

**목표:** 모바일 폭(< 820px)에서 "도구" 팝오버가 지금은 데스크톱의 `DrawToolbar`를 아무 수정 없이 그대로 넣은 것이라, 세 개의 카드(그리기·선택/조작·편집)에 담긴 버튼 수십 개가 한 번에 다 보인다 — 실제 모바일 드로잉 앱(Procreate·ibisPaint·MediBang 등)이 쓰는 "소수의 주요 도구 상시 노출 + 도구별 옵션만 자동으로 드러남" 방식과 다르다. 이 문서는 `DrawToolbar`를 모바일에서 어떻게 재구성할지 정의한다.

> 이 작업은 [`2026-09-18-nemo-nemo-beam-mobile-shell-design.md`](./2026-09-18-nemo-nemo-beam-mobile-shell-design.md)(Phase 1, 셸 뼈대)가 "도구바 자체의 모바일 내부 구성은 별도 설계 문서에서 다룬다"고 명시적으로 미뤄둔 부분이다. Phase 1과 그 이후 다듬기(모드 토글 단일화, 팝오버 위치·크기 조정 등)는 이미 완료돼 있고, 이 문서는 그 위에서 "도구" 팝오버 하나의 내부만 다룬다.

## 현재 상태

`DrawToolbar.tsx`는 도구를 세 그룹으로 나눠 desktop 상단에 가로로 나열한다:

- **그리기 카드**: `PRIMARY_DRAW_TOOLS`(펜슬·지우개·채우기, 항상 보임) + `COLLAPSIBLE_DRAW_TOOLS`(직선·사각형·원·텍스트·그라데이션, `compact`일 때만 "더보기" 뒤로 접힘 — `compact`는 desktop 폭이 `TOOLBAR_COMPACT_WIDTH`(1170px)보다 좁을 때만 켜진다).
- **선택·조작 카드**: `SELECT_TOOLS`(선택·올가미·이동·자동선택), 항상 보임, 접히지 않음.
- **편집 카드**: 실행취소·다시실행·격자·십자선(항상 보임) + `ScopedActionButton`으로 만든 지우기(위험) + "더보기" 뒤에 접힌 반전H·반전V·회전↺·회전↻·정렬(각각 `TransformMoreButtons`의 `ScopedActionButton`).

도구별 하위 옵션(`secondarySections` — 브러시 크기, 도형 채우기/그라데이션, 선택 모드+전역 동일색, 대상 레이어 세그먼트 컨트롤)은 이 세 카드 어디에도 속하지 않고, `createPortal`로 **캔버스 영역 하단 중앙에 떠 있는 별도 DOM 노드**(`secondaryPortalTarget`, `Editor.tsx`가 관리)에 그려진다. 선택된 도구가 바뀌면 이 포털 내용도 즉시 바뀐다(추가 탭 없이 자동).

`ScopedActionButton`(지우기·반전·회전·정렬이 공통으로 쓰는 컴포넌트)은 아이콘 버튼 + 폭 3px짜리 캐럿을 눌러 펼치는 작은 드롭다운으로 "대상 레이어"(현재/참조/전체)를 고른다 — desktop의 좁은 카드 폭에 맞춘 압축된 형태다.

`Editor.tsx`는 `toolPanel`이라는 top-level 변수 하나로 `<DrawToolbar .../>`를 한 번만 만들어 desktop 레이아웃과 모바일 셸(`MobileEditorShell`)의 "도구" 팝오버가 똑같이 공유한다(Task 3에서 이미 완료됨). `LayerPanel`도 같은 패턴으로 `hideModeToggle`/`showFrameThumbnails`라는 모바일 전용 boolean prop을 받아 `narrow`일 때만 동작을 바꾼다 — 이번 작업도 이 관례를 그대로 따른다.

모바일 `더보기` 메뉴는 `Editor.tsx`의 `mobileMoreItems`(`MobileMoreItem[]`)로 정의되고, "편집" 항목은 이미 존재한다: 복사·캔버스 크기 수정·붙여넣기(모두 `activeTabIndex < 0`이면 비활성).

## 새 상태 — 상단 도구 행(상시 노출 7개 + 더보기)

모바일에서는 "그리기" 카드와 "선택·조작" 카드를 하나로 합쳐 상시 노출 도구를 7개로 만든다:

```
[펜슬][지우개][채우기]  [선택][올가미][이동][자동선택]  [더보기▾]
```

`더보기`를 누르면 `COLLAPSIBLE_DRAW_TOOLS`(직선·사각형·원·텍스트·그라데이션) 5개가 그 아래로 펼쳐진다 — desktop의 `compact` 모드가 이미 쓰는 `showMoreDrawTools` 확장 로직을 그대로 재사용한다(새 상호작용 패턴을 만들지 않는다).

"선택·조작" 카드는 더 이상 별도 카드로 렌더링하지 않는다 — 그 4개 버튼이 그리기 카드의 같은 줄에 합류한다.

## 새 상태 — 도구별 하위 옵션(팝오버 안, 도구 행 바로 아래에 자동 표시)

모바일에서는 `secondarySections`를 `createPortal`로 캔버스에 보내지 않고, **이 컴포넌트 자신의 JSX 안에서** 도구 행 바로 아래에 그대로 렌더링한다. 내용은 desktop과 동일하다(브러시 크기, 채우기/그라데이션 옵션, 선택 모드+전역 동일색, 대상 레이어) — 위치만 "캔버스 하단 포털"에서 "이 팝오버 안"으로 바뀐다. 도구가 바뀌면 desktop처럼 자동으로 내용이 바뀐다(탭 한 번 더 누를 필요 없음).

이렇게 바꾸는 이유: 모바일에서는 `secondaryPortalTarget` 자체가 캔버스 영역 하단(`absolute inset-x-0 bottom-2`)에 있는데, 캔버스 영역 바로 아래가 하단 독이라 포털 내용과 "도구" 팝오버가 화면 같은 구역(하단)에서 서로 겹치거나 시각적으로 두 개의 뜬 상자가 나란히 보여 혼란스럽다. 팝오버 안으로 옮기면 이 문제가 사라지고, "도구 팝오버 = 도구 선택 + 그 도구의 모든 것"이라는 하나의 완결된 단위가 된다.

## 새 상태 — 편집 카드는 팝오버에서 제거, `더보기 > 편집`으로 통합

격자 표시·십자선·지우기·반전H·반전V·회전↺·회전↻·정렬을 "도구" 팝오버에서 완전히 뺀다. 대신 기존 `더보기 > 편집`(복사·캔버스 크기 수정·붙여넣기) 목록에 항목으로 추가한다:

```
더보기 > 편집
─────────────────────────
복사
캔버스 크기 수정
붙여넣기
─────────────────────────
격자 표시                    ⏻ (Switch)
십자선                       ⏻ (Switch)
─────────────────────────
지우기(위험)          [현재][참조][전체]
반전(좌우)            [현재][참조][전체]
반전(상하)            [현재][참조][전체]
회전(반시계)          [현재][참조][전체]
회전(시계)            [현재][참조][전체]
정렬                  [현재][참조][전체]
```

- **격자 표시·십자선**: `showGrid`/`showCrosshair` 상태를 그대로 쓰는 단순 on/off 토글 — `LayerPanel`의 핑퐁·어니언 스킨 토글 행과 같은 스타일(라벨 + 오른쪽 `Switch`)로 만든다.
- **지우기·반전·회전·정렬**: desktop의 `ScopedActionButton`과 같은 데이터(`transformScopes`, `onTransformScopeChange`, 각 실행 콜백)를 쓰지만, 좁은 캐럿 드롭다운 대신 리스트 행 안에 바로 보이는 3버튼 세그먼트 컨트롤(현재|참조|전체)로 편다 — 모바일 리스트 행은 desktop 툴바 카드보다 폭이 훨씬 넓어(팝오버가 화면 대부분 폭을 쓸 수 있음) 캐럿으로 접어둘 필요가 없다. 행을 누르면(라벨 또는 아이콘 부분) desktop과 동일하게 그 즉시 실행되고, 세그먼트 버튼을 누르면 대상만 바뀐다(실행 안 함) — desktop의 "아이콘 클릭 = 실행, 캐럿 = 대상 선택" 구분을 그대로 유지한다.
- **참조 대상이 없는데 "참조"가 선택된 경우**: desktop처럼 실행(아이콘/라벨 클릭)만 비활성화하고 세그먼트 자체는 계속 선택 가능하게 둔다(모바일에서도 레이어 목록의 전구 아이콘으로 "참조 레이어" 지정 자체는 여전히 가능하므로 — "레퍼런스"(트레이싱 이미지) 기능 제거와는 무관한, 살아있는 기능이다).
- 실행취소·다시실행은 이미 모바일 상단 바에 있으므로 이 목록에 다시 넣지 않는다.

`DrawToolbar`가 이미 갖고 있는 `SegmentedControl`(지금은 파일 내부에 export 없이 정의됨, `{ label, value, onChange }` — 자기 라벨 텍스트 + 현재/참조/전체 버튼 3개를 함께 그린다)을 export해 `Editor.tsx`의 모바일 편집 목록에서도 재사용한다. 다만 편집 목록의 각 행은 이미 "반전(좌우)"처럼 행 자체가 라벨을 갖고 있어, `SegmentedControl`을 그대로 쓰면 같은 줄에 라벨이 두 번(행 라벨 + `SegmentedControl` 내부 "대상 레이어" 라벨) 나온다 — 버튼 3개(현재/참조/전체)만 필요하고 안쪽 라벨·도움말 아이콘은 중복이라 뺀다. 구체적으로 `SegmentedControl`의 라벨+도움말 부분을 선택적으로 감출 수 있게 하거나(예: `label` prop을 옵셔널로 바꿔 없으면 그 `<span>`을 아예 렌더링하지 않음), 버튼 3개 렌더링 부분만 별도로 뺀 작은 헬퍼로 분리한다 — 정확한 방법은 구현 태스크에서 정한다. 새 컴포넌트를 새로 설계하지는 않는다(기존 버튼 3개 스타일 재사용이 핵심).

## 새 상태 — 구현 방식

`DrawToolbar`에 `mobileLayout?: boolean` prop을 추가한다(`LayerPanel`의 `hideModeToggle`/`showFrameThumbnails`와 동일한 패턴 — 데스크톱은 이 prop이 없으니 지금과 100% 동일하게 동작한다):

```ts
// 모바일 셸 전용 — true면:
// 1) 그리기 카드와 선택·조작 카드를 한 줄로 합친다(별도 카드 구분 없음)
// 2) 편집 카드(격자·십자선·지우기·반전·회전·정렬) 자체를 렌더링하지 않는다
//    (Editor.tsx가 이 값들을 더보기>편집 목록에 직접 그린다)
// 3) secondarySections를 캔버스 포털이 아니라 이 컴포넌트 안에 바로 그린다
mobileLayout?: boolean;
```

`Editor.tsx`의 `toolPanel` top-level 변수(desktop·모바일이 공유)에 `mobileLayout={narrow}`를 추가한다 — `layerPanel`에 `hideModeToggle={narrow}`를 추가했던 것과 정확히 같은 자리, 같은 방식이다. `compact` prop도 `narrow`일 때 함께 `true`가 되도록 전달값을 `compact={compact || narrow}`로 바꿔, 모바일에서는 `COLLAPSIBLE_DRAW_TOOLS`가 항상 "더보기" 뒤에 접히게 한다(모바일 폭에서 `TOOLBAR_COMPACT_WIDTH`(1170px) 조건은 항상 참이 되어 사실 원래도 그랬겠지만, 명시적으로 보장한다).

`mobileMoreItems`의 "편집" 항목 `content`에 격자·십자선 토글 두 줄과 지우기·반전×2·회전×2·정렬 여섯 줄을 추가한다 — 각 줄이 필요로 하는 상태·콜백(`showGrid`, `onToggleGrid`, `showCrosshair`, `onToggleCrosshair`, `onClearCanvas`, `transformScopes`, `onTransformScopeChange`, `onFlipHorizontal`, `onFlipVertical`, `onRotate90`, `onAlignContent`, `hasReferenceLayers`)은 모두 이미 `Editor.tsx`가 갖고 있다(desktop의 `toolPanel`/편집 카드가 쓰던 것과 동일한 값).

## 영향받지 않는 것

- desktop 폭(≥ 820px)에서 `DrawToolbar`의 동작·레이아웃 — `mobileLayout` prop이 없으면(`undefined`) 지금과 완전히 동일하다.
- 색상환·레이어 패널(이미 Phase 1 이후 다듬기에서 모바일 대응 완료).
- 이 문서 범위 밖: 바탕화면(갤러리) 화면을 모바일 홈스크린 스타일로 바꾸는 작업, PC/모바일용 배경화면 파일을 분리해 화면 폭에 맞는 것만 보여주는 작업 — 둘 다 별도로 브레인스토밍한다.

## 테스트 계획

자동화된 테스트 스위트가 없는 프로젝트 — `npx tsc --noEmit`·`npm run lint`로 정적 검증하고, 브라우저(390px 폭, 1280px 폭)로 다음을 확인한다:

1. 390px 폭에서 "도구" 팝오버를 열면 펜슬·지우개·채우기·선택·올가미·이동·자동선택 7개 + 더보기가 한 줄에 보이는지.
2. 더보기를 누르면 직선·사각형·원·텍스트·그라데이션 5개가 펼쳐지고, 그 중 하나를 고르면 활성 도구가 바뀌면서 더보기 패널이 닫히는지(desktop의 기존 확장 동작과 동일한지).
3. 펜슬/사각형/그라데이션/선택 도구를 각각 골라, 그 도구의 하위 옵션(브러시 크기 / 채우기+그라데이션 옵션 / 선택 모드+전역 동일색)이 도구 행 바로 아래에 자동으로 뜨는지, 도구를 바꾸면 즉시 내용이 바뀌는지.
4. 더보기 > 편집을 열어 격자 표시·십자선 토글이 실제로 캔버스에 반영되는지, 지우기·반전·회전·정렬이 실행되는지, 각 행의 현재/참조/전체 세그먼트를 바꾸면(레이어 목록에서 미리 전구 아이콘으로 레이어 하나를 참조로 지정해 둔 뒤) 그 대상에 맞게 동작하는지, 참조 대상이 없을 때 "참조"를 고르면 실행이 비활성화되는지.
5. 1280px 폭에서 desktop 레이아웃(그리기·선택·조작·편집 세 카드, 캔버스 하단 포털 하위 옵션)이 이 작업 이전과 완전히 동일한지(회귀 없음).
6. 창 폭을 820px 위아래로 오가며 도구 팝오버가 열려 있지 않은 상태에서 정상 전환되는지(레이아웃 깨짐 없음).
