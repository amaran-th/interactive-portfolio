# 자산 시뮬레이터 v3 4라운드: 명칭 변경, 레이아웃 마무리, 온보딩, 아이콘

이 문서는 v1, v2, v3 1~3라운드(시나리오 비교 UI까지)가 전부 구현·리뷰 완료된 뒤 진행하는 v3의 마지막 라운드다. 처음 v3를 4단계로 쪼갤 때 계획했던 "명칭 변경, 사이드바 2단 분할, 기본값 채우기, 새로고침 경고, 아이콘 활용"을 다룬다.

## 목표

- "자산군" 입력 카드의 명칭·문구를 "현재 자산"으로 바꾼다.
- 입력 패널(왼쪽 컬럼)을 2단으로 나눠 넓어진 화면을 더 잘 쓴다.
- 앱을 처음 열었을 때 빈 화면 대신 예시 데이터로 채워진 상태로 시작한다.
- 데이터를 수정한 뒤 새로고침·창 닫기를 시도하면 경고를 띄운다.
- 카드 제목·빈 상태 메시지·주요 버튼에 아이콘을 붙여 시각적으로 구분한다.

## 1. 명칭 변경: "자산군" → "현재 자산"

개별 계좌(`AssetClass`)를 등록하는 카드와 그 주변 문구만 바꾼다. "그룹"(`Group`, 색상·선택적 묶음 기능)이라는 용어와 관련 코드(`Group` 타입, `groups` 변수명 등)는 전혀 건드리지 않는다 — 서로 다른 개념이다.

## 2. 입력 패널 2단 분할

`InputPanel.tsx`는 지금 자산·수입·지출·이체 규칙 4개 카드를 세로 한 줄로 쌓는다(`flex flex-col gap-4`). 이를 2×2 그리드로 바꾼다: 자산/수입이 위, 지출/이체 규칙이 아래(기존 순서 유지, 배치만 그리드로).

카드가 2열로 나란히 놓이려면 지금의 360px 고정폭으로는 좁다. `AssetSimulator.tsx`의 3열 그리드(`md:grid-cols-[360px_1fr_320px]`)에서 입력 패널 컬럼 폭을 `640px`로 늘린다(`md:grid-cols-[640px_1fr_320px]`). 가운데 차트 영역은 `1fr`이라 자동으로 줄어들 뿐, 다른 컬럼(차트 그리드 2열, 이력 패널)의 내부 구조는 바뀌지 않는다.

## 3. 온보딩: 첫 로드 시 예시 데이터

앱을 처음 열었을 때(즉, `AssetSimulator`의 초기 `scenarios` state를 만들 때) 완전히 빈 시나리오 대신 아래 예시 데이터로 채워진 "시나리오 1"을 만든다:

- 자산: "현금"(KRW, 기본 계좌, 초기 잔액 10,000,000원)
- 수입: "월급"(3,000,000원, 매월, 무기한, 다음 달부터 시작)
- 지출: "생활비"(1,000,000원, 매월, 무기한, 다음 달부터 시작)

사용자는 이 예시 항목들을 그대로 두거나 자유롭게 수정·삭제할 수 있다. "+ 새 시나리오" 버튼으로 만드는 이후 시나리오는 지금처럼 완전히 빈 상태로 시작한다(v3 3라운드에서 확정된 동작, 변경 없음) — 이 온보딩 시딩은 앱이 처음 마운트될 때 딱 한 번만 적용된다.

## 4. 새로고침·창 닫기 경고

사용자가 무언가를 실제로 수정했을 때만 경고한다(단순히 슬라이더를 움직이거나 시뮬레이션 범위를 바꾸는 것은 "수정"으로 치지 않는다 — 화면 보기 옵션일 뿐 데이터 변경이 아니다).

- `AssetSimulator.tsx`에 `isDirty` state를 추가한다.
- 시나리오의 실제 데이터를 바꾸는 지점(활성 시나리오 갱신을 담당하는 공용 헬퍼, 그리고 시나리오 생성·복제·삭제·이름변경 핸들러) 각각에서 `isDirty`를 `true`로 설정한다.
- `window.beforeunload` 이벤트에 `isDirty`가 `true`일 때만 `e.preventDefault(); e.returnValue = "";`를 호출하는 리스너를 `useEffect`로 등록한다.
- 온보딩 예시 데이터 자체를 채우는 동작은 "사용자의 수정"이 아니므로 `isDirty`를 `true`로 만들지 않는다 — 초기 `useState` 값으로 직접 시딩하고, 어떤 핸들러도 거치지 않게 한다.

카드 제목, 빈 상태 메시지, 주요 액션 버튼에 이모지 하나씩을 붙인다. 데이터 모델·기능은 바뀌지 않고 문구 앞에 이모지만 추가된다.

## 엣지 케이스

- 온보딩 예시 데이터의 자산·수입·지출은 다른 사용자 입력 데이터와 완전히 동일하게 취급된다 — 삭제·수정·색상 변경 모두 정상 동작해야 한다(특별 취급 없음).
- `beforeunload` 경고는 브라우저 기본 확인창을 쓴다(커스텀 모달 아님) — 브라우저별로 문구가 고정되어 있어 `e.returnValue`에 넣은 문자열이 그대로 보이지 않을 수 있는 것은 웹 표준의 알려진 제약이며 이번 범위에서 손댈 수 없다.
- 2단 입력 패널에서 카드 하나가 유난히 길어져도(예: 이체 규칙이 많을 때) 그리드 셀 높이가 서로 다른 것은 정상이다 — 높이를 맞추는 별도 처리는 하지 않는다.

## 범위 밖 (Non-goals)

- 온보딩 예시 데이터를 여러 종류(예: "1인 가구", "신혼부부" 등 프리셋 여러 개) 중에서 고르게 하는 기능은 넣지 않는다 — 고정된 예시 하나만 쓴다.
- `beforeunload` 경고를 실제 서버 저장/로컬스토리지 영속화로 대체하는 기능은 넣지 않는다(이 앱은 원래 새로고침 시 초기화되는 것이 전제 — 경고만 추가할 뿐 저장 기능 자체는 이번 범위 밖).
- 아이콘 목록에 없는 위치(예: 개별 리스트 항목 하나하나)에는 아이콘을 추가하지 않는다.
