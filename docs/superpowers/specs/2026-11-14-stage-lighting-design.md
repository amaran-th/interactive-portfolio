# 무대조명 시뮬레이터 설계 (1단계)

> **폐기됨 (2026-11-18):** 같은 경로(`/stage-lighting`, `components/works/11_StageLighting/`)에 이미 '조명 연습실'이 있어 이 설계로 새로 만들지 않았다. 요청 사항 중 '사이드바 탭 3개(무대 설정·무대 요소·조명기)'와 '조명기 자유 배치·몸체 끌기'만 기존 조명 연습실에 반영했다(커밋 `115ac21`). 나머지 내용은 참고용이다.

- 날짜: 2026-11-14 (2026-11-16 수정: 패널 탭 3개, 조명기 자유 배치)
- 대상: `apps/services`
- 범위: 1단계 — 무대·소품·등장인물·기본 조명기·큐 재생·연무·시점·저장. **무빙 라이트와 고보는 2단계**(별도 설계)로 미룬다.

## 목표

공연 무대 조명 연출을 브라우저에서 연습하는 3D 도구를 만든다. 무대를 고르고, 소품과 등장인물을 배치하고, 조명기를 걸어 포커스·밝기·색을 정한 뒤, 장면(큐)을 저장해 GO로 페이드하며 넘겨 본다.

### 성공 기준

- `/stage-lighting`이 열리고, 메인의 창작 카테고리와 sitemap에 나온다.
- 조명기 16개와 그림자를 켠 상태에서 데스크톱 Chrome이 끊김 없이 움직인다(30fps 이상).
- 새로고침해도 공연(무대·오브젝트·조명·큐)이 그대로다.
- 데이터 모델·큐 보간·리깅 좌표는 `node:test`로, 화면은 Playwright로 확인한다.

## 1. 좌표와 단위

- 단위는 미터.
- 무대 앞 가장자리 가운데가 원점이다. x는 관객이 볼 때 오른쪽, y는 위, z는 객석 쪽(+)이다. 무대는 z ≤ 0에 놓인다.
- 무대 바닥 높이는 `deckHeight`(기본 0.9m)이고, 객석 바닥은 y = 0이다.

## 2. 무대

| 항목 | 값 |
|---|---|
| 모양 | 프로시니엄(액자형, 기본) / 돌출형 / 원형 |
| 폭 | 6~20m, 기본 12 |
| 깊이 | 4~16m, 기본 8 |
| 무대 바닥 높이 | 0~1.5m, 기본 0.9 |
| 바닥색 | 기본 `#3a3a3a` |
| 배경막(사이클로라마) | 켜기/끄기, 색 기본 `#e8e8e8` |

- 프로시니엄:
  - 직사각형 무대에 앞쪽 액자(높이 6m, 기둥 폭 1m)가 있다.
  - 배경막은 무대 뒤 끝(z = −깊이)에 무대 폭 × 7m로 선다.
- 돌출형: 직사각형 무대 앞에 폭의 절반 × 깊이의 절반짜리 돌출부가 객석 쪽으로 나온다. 액자는 없다.
- 원형: 지름 = 폭인 원판이 객석 가운데에 놓인다(중심 z = −반지름). 배경막 대신 사방이 객석이다(배경막 설정은 숨긴다).
- 객석: 무대 앞쪽(+z)에 계단식 좌석 블록 10줄을 단순한 상자로 그린다. 원형 무대면 사방에 둔다.

## 3. 오브젝트 (등장인물·소품)

- 공통 속성: 위치(x, z — 무대 바닥 위), 방향(y축 회전, 15° 단위 스냅), 크기 배율(0.5~2), 색
- 최대 40개

### 등장인물

- 기본 도형(구·원기둥·캡슐)으로 만든 마네킹이다.
- 키 1.4~2.0m, 기본 1.75
- 자세 5가지: 서기, 앉기(의자 높이 0.45m에 맞춤), 팔 벌리기, 걷기, 눕기
- 이름표(선택): 3D 위에 작은 글자로 표시하며, 끌 수 있다.

### 소품 10종

| 종류 | 기본 크기(가로×세로×높이, m) |
|---|---|
| 의자 | 0.5×0.5×0.9 |
| 탁자 | 1.4×0.8×0.75 |
| 침대 | 2.0×1.4×0.6 |
| 계단(3단) | 1.2×0.9×0.6 |
| 단상 | 2×2×0.4 |
| 나무 | 1.5×1.5×3 |
| 문틀 | 1.2×0.2×2.2 |
| 기둥 | 0.4×0.4×4 |
| 상자 | 0.6×0.6×0.6 |
| 가로등 | 0.4×0.4×3.2 |

가로등은 모양만 있고 빛을 내지 않는다(조명은 조명기로만).

## 4. 조명

### 조명기 배치 — 자유 위치 + 직접 조작

- 조명기는 3D 공간 어디에나 놓는다. 위치(x, y, z)와 포커스 점(조준 고리)을 각각 가진다.
- 위치 범위:
  - x: −(폭/2 + 10) ~ +(폭/2 + 10)
  - y: 0.2 ~ 10
  - z: −깊이 − 2 ~ +12
  - 범위를 벗어나면 가장자리로 맞춘다.
- 포커스 점:
  - 바닥 위 (x, z)와 겨누는 높이(바닥에서 0~2m, 기본 1.0)로 정한다.
  - 조명기는 (x, 바닥 + 높이, z)를 향한다.
  - 조준 고리는 그 바닥 위치에 그린다.
- 높이 바로 맞추기 버튼(`rig.ts`가 무대 설정으로 계산한다). 버튼은 높이(y)만 바꾸고 x·z는 그대로 둔다.

| 버튼 | 높이 |
|---|---|
| 바닥 | 무대 바닥 + 0.2 |
| 붐 | 무대 바닥 + 2.5 |
| 배튼 | 6.5 |
| FOH | 7 |

- 새 조명기를 추가하면 종류별 기본 자리에 놓인다.
  - 팔로우 스포트: 객석 위 FOH 높이, z = +6, x = 0
  - 호리존트: 배튼 높이, z = −깊이 × 0.85, 배경막을 향함
  - 나머지: 배튼 높이, z = −깊이 × 0.3
  - 포커스는 무대 가운데에 둔다.
  - 이미 조명기가 있는 자리면 x를 1m씩 옆으로 비킨다.

### 조명기 5종

| 종류 | 빔 각도 | 가장자리 부드러움(0~1) | 최대 광도(cd) |
|---|---|---|---|
| 프로파일 | 19~50°, 기본 26 | 0~0.4, 기본 0.1 | 3,000 |
| 프레넬 | 15~60°, 기본 40 | 0.5~0.9, 기본 0.7 | 2,500 |
| PAR | 10~60°, 기본 30 | 0.3~0.6, 기본 0.45 | 4,000 |
| 팔로우 스포트 | 4~20°, 기본 10 | 0~0.3, 기본 0.15 | 6,000 |
| 호리존트 | 70~120°, 기본 100 | 0.8~1, 기본 0.9 | 2,500 |

- 종류별로 걸 수 있는 위치 제한은 없다.

- 광도 값은 구현 때 화면 노출에 맞춰 함께 조정할 수 있다. 조정하면 이 표를 고친다.
- 조명기마다 조절하는 값:
  - 밝기 0~100%(10% 단위 버튼 + 1% 슬라이더)
  - 색
  - 빔 각도
  - 가장자리 부드러움
  - 이름(기본 `종류 번호`)
- 최대 16개.

### 그림자와 연무

- 그림자: 전체 켜기/끄기(기본 켬). 켜면 모든 조명기가 512px 그림자 맵을 쓴다.
- 연무:
  - 켜면 조명기마다 빔 모양 반투명 원뿔을 더한다.
  - 원뿔은 가산 혼합이고, 축에서 멀수록·광원에서 멀수록 옅어진다.
  - 농도는 0~1이고 기본 0.4다.
  - 원뿔의 밝기·색은 그 조명기의 현재 밝기·색을 따른다.
  - 끄면 원뿔을 그리지 않는다.

## 5. 큐

- 큐에 담는 것:
  - 번호(1부터)와 이름
  - 페이드 시간(0~30초, 기본 3)
  - 조명기마다 밝기·색
- 무대·오브젝트·포커스·빔 각도는 큐에 담지 않는다. 장면 전환이 아니라 조명 상태 전환만 연습한다.
- **현재 상태(라이브)**:
  - 조명기 패널에서 바꾸는 값이다.
  - 마지막으로 불러온 큐와 다르면 큐 막대에 '바뀜' 표시가 붙는다.
- 버튼:
  - 'GO': 다음 큐로 그 큐의 페이드 시간 동안 넘어간다. 밝기는 선형으로 보간하고, 색은 선형 RGB 공간에서 보간한다.
  - '이전': 앞 큐로 1초 동안 돌아간다.
  - '큐 저장': 현재 상태를 새 큐로 맨 뒤에 넣는다.
  - '덮어쓰기': 현재 상태를 선택한 큐에 덮어쓴다.
  - '삭제', 순서 바꾸기(위·아래)
- 페이드 중 GO를 누르면 진행 중인 페이드를 끝 상태로 바로 맞추고 다음 페이드를 시작한다.
- 페이드 중에 조명기 값을 직접 바꾸면 페이드를 멈추고 그 값부터 라이브로 이어 간다.
- 큐에 없는 조명기(큐를 만든 뒤 추가한 조명기)는 그 큐에서 밝기 0으로 본다.
- 조명기를 지우면 모든 큐에서 그 조명기 값도 지운다.
- 단축키: Space = GO, Backspace = 이전. 글자 입력칸에서는 동작하지 않는다.
- 최대 99개.

## 6. 화면

### 패널 탭 3가지

- 오른쪽 패널(데스크톱 320px)은 **무대 설정 / 무대 요소 / 조명기** 탭으로 나눈다.
- 단축키는 `1`·`2`·`3`이고, 글자 입력칸에서는 동작하지 않는다.
- 탭은 패널에 보이는 내용만 바꾼다. 3D에서는 어느 탭에서든 인물·소품·조명기를 누를 수 있다.
- 누르면 그 대상을 고르고, 그 대상의 탭으로 자동으로 넘어간다.

| 탭 | 패널 내용 |
|---|---|
| 무대 설정 | 모양, 크기, 바닥 높이, 색, 배경막, 그림자, 연무 |
| 무대 요소 | '등장인물 추가', '소품 추가'(종류 고르기), 목록, 선택한 대상의 속성(키·자세·크기·색·방향·이름표), '삭제' |
| 조명기 | '조명기 추가'(종류 고르기), 목록(이름·밝기 막대·색 점), 선택한 조명기의 속성(밝기·색·빔 각도·부드러움·이름·높이 버튼·겨누는 높이), '삭제' |

- 조준 고리는 조명기 탭에서만 보인다(늘 보이면 무대가 어수선하다). 조명기 몸체는 늘 보인다.
- 큐 막대는 탭과 관계없이 늘 아래쪽에 있다. 큐 목록(가로 스크롤), GO, 이전, 큐 저장, 덮어쓰기, 페이드 시간, '바뀜' 표시가 들어간다.
- 모바일(폭 < 768px)에서는 패널이 3D 뷰 아래로 내려가고, 화면 안에서 스크롤한다.
- 탭과 시점은 저장하지 않는다. 처음 열면 무대 설정 탭, 설계 시점이다.

### 시점

| 시점 | 카메라 |
|---|---|
| 설계(기본) | 원근 카메라. 빈 곳을 끌면 회전, 휠로 확대, 오른쪽 드래그로 이동(OrbitControls) |
| 관객석 | 객석 가운데 줄 눈높이(좌석 높이 + 1.2m)에서 무대 중앙을 본다. 줄(1~10) 슬라이더로 앞뒤를 바꾸고, 시점은 고정이다 |
| 평면도 | 위에서 내려다보는 직교 카메라. 확대·이동만 된다 |

### 직접 조작

- 3D에서 대상을 누르면 선택하고 패널이 그 속성으로 바뀐다. 대상을 누른 채 끌면 OrbitControls 회전 대신 대상이 움직인다. 빈 곳을 끌 때만 시점이 돈다.
- 마우스를 올리면 대상이 밝게 테두리 쳐지고 커서가 손 모양이 되어, 잡을 수 있는 것이 보인다.
- **인물·소품:**
  - 바닥 평면 위에서 움직인다. 무대 밖으로는 나가지 않는다.
  - 0.25m 격자에 맞춰지고, Alt를 누르면 격자를 끈다.
- **조명기 몸체:**
  - 지금 높이의 수평면 위에서 움직인다.
  - Shift를 누른 채 끌면 위아래만 움직인다.
  - 0.25m 격자에 맞춰진다.
- **조준 고리:** 바닥 위에서 움직이고, 조명기는 바로 따라 돈다.
- 끄는 동안 위치 숫자(x, y, z)를 대상 옆에 작게 보여 준다.
- 관객석 시점에서는 선택만 되고 끌기는 막는다(보는 시점이라서).
- 선택한 대상은 Delete 키나 패널의 '삭제'로 지운다. Esc는 선택을 푼다.
- 끌기·회전·삭제·추가는 실행 취소(Ctrl/⌘+Z)·다시 실행(Ctrl/⌘+Shift+Z)할 수 있고, 최대 100단계다. 조명 값 변경(밝기·색 등)과 큐 편집도 같은 기록에 들어간다.

## 7. 저장과 내보내기

- localStorage 키는 `stage-lighting-show` 하나다. 공연 전체(무대·오브젝트·조명기·큐·라이브 값·연무·그림자)를 JSON으로 담는다.
  - 형식 버전 `v: 1`
  - 바뀐 뒤 500ms에 저장하고, `pagehide`·`visibilitychange`(hidden)·언마운트 때 기다리던 저장을 바로 쓴다.
  - 읽을 때 형식이 맞지 않으면 기본 공연으로 시작한다. 이때 예외를 내지 않는다.
- 기본 공연은 다음과 같다.
  - 프로시니엄 무대
  - 등장인물 2명, 의자 1개
  - 조명기 6개: FOH 프로파일 2, 배튼 1 프레넬 2, 배튼 3 호리존트 2
  - 큐 3개: 1 = 객석 조명 느낌의 전체 밝음, 2 = 따뜻한 낮, 3 = 파란 밤
- 'PNG로 저장'은 지금 시점의 화면을 `stage-lighting-YYYYMMDD-HHmm.png`로 내려받는다.
- 개인정보처리방침의 `STORAGE_ITEMS`에 키를 추가한다.

| `show.ts` | 공연 타입, 기본 공연, 직렬화·검증. 순수, `node:test` |
| `history.ts` | 공연 스냅숏 기반 실행 취소·다시 실행(100단계). 순수, `node:test` |
| `useStageScene.ts` | three.js 장면: 무대·객석·오브젝트·조명기·조준 고리·연무 원뿔·카메라 3종·선택/끌기·PNG |
| `meshes.ts` | 마네킹 자세·소품 10종·조명기 몸체 메시 생성 |
| `StageLighting.tsx` | 패널·큐 막대·입력·저장 |

- 라우트는 `app/stage-lighting/page.tsx`와 `guide.ts`.
- `lib/tools.ts`에 `category: "creative"`로 등록한다.
- three.js는 이미 의존성에 있다(`three`, `@types/three`). `OrbitControls`는 `three/examples/jsm/controls/OrbitControls.js`에서 가져온다.
- 렌더러: `ACESFilmicToneMapping`. 그림자는 `PCFSoftShadowMap`. 객석·무대 바닥은 아주 어두운 환경광만 받아 조명기 효과가 잘 보이게 한다.
- WebGL을 쓸 수 없으면 안내 문구를 보여 준다(모노리즘과 같은 방식).

## 9. 안내 문구

- `guide.ts`(합니다체):
  - 사용 방법: 무대 고르기 → 오브젝트 배치 → 조명기 걸고 포커스 → 밝기·색 → 큐 저장 → GO
  - 알아 두면 좋은 점: 조명기 종류별 쓰임, 키·필·백 라이트와 배경막 조명의 기본, 페이드 시간, 연무, 그림자 성능
  - FAQ: 저장 위치, 느릴 때, 큐에 무대 배치가 안 담기는 이유
- `TOOLS` 항목은 해요체로 쓴다.

## 10. 검증

1. `node:test`:
   - `fixtures`: 종류별 범위 정규화(밖의 값은 가장자리로), 팔로우 스포트·호리존트 위치 제한
   - `rig`:
     - 무대 크기별 높이 버튼 값·기본 자리
     - 범위 밖 위치는 가장자리로
     - 격자 맞춤(0.25m)과 끄기
     - 기본 자리가 겹치면 옆으로 비킴
   - `history`:
     - 기록·실행 취소·다시 실행
     - 새 기록이 다시 실행 목록을 비움
     - 100단계 제한
   - `cues`:
     - 보간 0·0.5·1(밝기 선형, 색 선형 RGB)
     - 큐에 없는 조명기 = 0
     - 저장·덮어쓰기·삭제·이동
     - 조명기 삭제가 모든 큐에 반영됨
     - 99개 제한
   - `show`: 기본 공연 유효성, 직렬화 왕복, 잘못된 저장값(버전·범위·필수 필드·개수 초과)은 null
2. `npm run lint`, `npm run build` 통과. sitemap에 `/stage-lighting`이 있다.
3. Playwright(헤드리스 Chromium):
   - 첫 화면에 기본 공연이 그려진다.
   - 탭 전환에 따라 패널 내용이 바뀐다.
   - 3D에서 인물을 누르면 무대 요소 탭이 열리고, 끌면 위치가 바뀐다.
   - 조명기 몸체·조준 고리를 끌면 위치·포커스가 바뀐다.
   - Ctrl+Z로 되돌린다.
   - 조명기 추가·밝기 변경 후 저장값에 반영된다.
   - 큐 저장 → 밝기 바꾸기 → GO로 큐가 넘어간다(페이드 0초 큐로 즉시 확인).
   - 새로고침 후 유지된다.
   - 시점 3종 전환에서 오류가 없다.
   - PNG를 내려받는다.
   - 모바일 375px에서 가로 스크롤이 없다.
   - 콘솔 오류가 없다.
4. 사용자 확인: 조명 느낌(광도·색), 연무 모양, 16개+그림자 성능, 끌어서 옮기기 손맛
