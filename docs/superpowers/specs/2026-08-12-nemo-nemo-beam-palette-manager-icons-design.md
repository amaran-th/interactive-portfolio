# 네모네모빔 — 팔레트 세트 행 아이콘을 방향이 분명한 짝으로 교체

**목표:** "즐겨찾기 관리" 드롭다운의 세트별 행에서 불러오기·덮어쓰기 아이콘 의미가 한눈에 안 들어온다는 피드백을 반영해, 두 동작이 반대 방향임이 아이콘만 봐도 드러나는 짝으로 바꾼다.

## 현재 상태(문제)

`ColorWheel.tsx`의 세트 행은 불러오기에 `Download`, 덮어쓰기에 `Save` 아이콘을 쓴다(`ColorWheel.tsx:406,413`). 사용자 피드백: 파일 저장/내보내기와 헷갈리는 게 아니라, 두 아이콘 자체만으로는 각각 무슨 동작인지 가늠하기 어렵다는 것 — 특히 둘이 서로 반대 방향의 동작(세트→즐겨찾기 교체 / 즐겨찾기→세트 저장)이라는 관계가 아이콘에서 안 보인다.

## 아이콘 교체

브라우저 목업으로 세 후보(화살표+선 대칭 쌍 / 폴더 열기+저장 / 가져오기+내보내기)를 실제 행 스타일로 비교해 첫 번째 안을 골랐다:

- **불러오기**(세트 색으로 즐겨찾기 전체 교체): `Download` → `ArrowDownToLine`
- **덮어쓰기**(지금 즐겨찾기 내용으로 세트 저장): `Save` → `ArrowUpFromLine`

두 아이콘은 같은 밑줄(선) 도형을 공유하고 화살표 방향만 반대라, 나란히 놓으면 "이 선(즐겨찾기) 쪽으로 내려오는 동작"과 "이 선에서 위로 나가는 동작"이 서로 대칭적인 반대 관계로 읽힌다.

## 구현 범위

`ColorWheel.tsx`의 `lucide-react` import에서 `Download`, `Save`를 `ArrowDownToLine`, `ArrowUpFromLine`으로 바꾸고, 두 아이콘이 쓰이는 자리(각각 한 곳)의 컴포넌트 이름을 맞춰 바꾼다. 아이콘 크기·색상·버튼 스타일, `title` 툴팁 텍스트, 삭제(`Trash2`, 호버 시에만) 아이콘과 그 동작 로직은 전혀 손대지 않는다.

## 영향받지 않는 것

- 드롭다운 위치 계산, 행 레이아웃(스와치 미리보기·이름 말줄임), `handleLoadSet`/`handleOverwriteSet`/`handleDeleteSet` 로직 — 전혀 변경 없음.
- 다른 파일의 `Download`/`Save` 아이콘 사용(있다면) — 이 파일에서만 각 한 곳씩 쓰이므로 다른 곳에 영향 없음.

## 테스트 계획

자동화된 테스트 스위트가 없는 프로젝트 — `npx tsc --noEmit`·`npm run lint`·`npm run build`로 정적 검증하고, 브라우저에서 드롭다운을 열어 두 아이콘이 바뀐 모양으로 보이는지, 클릭했을 때 기존과 동일하게 동작(불러오기 시 즐겨찾기 교체, 덮어쓰기 시 세트 갱신)하는지 육안·DOM으로 확인한다.
